## 0. 准备

### 0.1 铸造测试 token（无需登录、无需验证码）

`dev-session` 已删除，测试用仓库根的临时工具签发 JWT（**用完删除**）：

```bash
cd /Users/yiliiang/Documents/lingce-api
# 临时工具已移出仓库，使用本机保留的路径
MINT_TOOL=$(ls /tmp/lingce-api-temp-tools-*/tmp_mint_token.go 2>/dev/null | tail -1)
test -n "$MINT_TOOL" || { echo "missing tmp_mint_token.go"; exit 1; }

# 平台 admin（不绑租户）
ADMIN=$(go run "$MINT_TOOL" 1 admin)
# A 机构员工（用 A 机构真实员工 id）
A=$(go run "$MINT_TOOL" <A员工id> employee <A租户id>)
# B 机构员工
B=$(go run "$MINT_TOOL" <B员工id> employee <B租户id>)

echo "export ADMIN=$ADMIN A=$A B=$B" > /tmp/sec_tokens.env && source /tmp/sec_tokens.env
```

注意：employee token 的 `user_id` 必须是 `employees` 表里真实存在的员工 id，否则权限判定会走空。

### 0.2 准备数据 id（在 dev 库查）

```sql
-- 两台机构
SELECT id, name FROM tenants WHERE deleted_at IS NULL ORDER BY id LIMIT 10;

-- 各自一名员工（取 id 用于铸造 token）
SELECT id, tenant_id, full_name, phone FROM employees
 WHERE tenant_id IN (<A>, <B>) AND deleted_at IS NULL ORDER BY id LIMIT 10;

-- B 机构的一条录音 / 一个随访任务 / 一个客户（用于"跨租户读取"用例）
SELECT id, tenant_id FROM recordings WHERE tenant_id=<B> AND deleted_at IS NULL ORDER BY id DESC LIMIT 3;

-- 一个平台病历模板（用于"租户不可改平台模板"用例）
SELECT id, code, tenant_id, status FROM emr_templates WHERE tenant_id = 0 LIMIT 3;

-- A 机构的一个客户分组（用于"分群成员跨租户"用例）
SELECT id, tenant_id, name FROM customer_groups WHERE tenant_id=<A> LIMIT 3;

-- HIS 号源（用于"挂号跨租户患者"用例）
SELECT id, tenant_id, doctor_id, work_date FROM his_schedules WHERE tenant_id=<A> AND status='open' LIMIT 3;
```

## 2. 手工验证清单（核心）

统一约定：`$A`/`$B` 是两台机构员工 token，`$ADMIN` 是平台 admin。**期望 = 修复后的行为**。

### P0 级（修复前任意员工即可跨机构）

| # | 用例 | 命令 | 期望 |
|---|---|---|---|
| 1 | 读他院录音分析 | `curl -s -o /dev/null -w '%{http_code}' -H "Authorization: Bearer $A" "http://127.0.0.1:18080/api/v1/recordings/<B录音id>/analysis"` | **403**（修复前 200 + 全文转写） |
| 2 | 读他院随访任务 | `curl ... "http://127.0.0.1:18080/api/v1/recording-tasks/<B任务id>?task_type=follow_up"` | **403** |
| 3 | 员工批量删录音 | `curl -X POST -H "Authorization: Bearer $A" -H 'Content-Type: application/json' -d '{"recording_ids":[<B录音id>]}' .../api/v1/recordings/actions/batch-delete` | **403**（admin-only） |
| 4 | 员工自提权 | `curl -X PUT -H "Authorization: Bearer $A" -d '{"role_id":<admin角色id>}' .../api/v1/employees/<自己id>/role` | **403** `Institution admin access required`；机构管理员操作**别院**员工同样 403 |

## 3. 审计中间件验证

1. 用平台 admin 带租户读一次敏感接口：

```bash
curl -s -H "Authorization: Bearer $ADMIN" \
  "http://127.0.0.1:18080/api/v1/compliance/check-items?tenant_id=<B>&page=1&page_size=1" > /dev/null
```

2. 1~2 秒后查库（或 `GET /api/v1/ops/system-logs` 过滤 `log_type=ops_read_audit`）：

```sql
SELECT id, tenant_id, actor_id, action_code, route_path, created_at
FROM system_action_logs
WHERE log_type = 'ops_read_audit'
ORDER BY id DESC LIMIT 10;
```

期望：多出 `action_code='ops.cross_tenant.read'`、`tenant_id=<B>`、`route_path` 为你请求的路径的一条记录。

## 5. 注意事项

- **反向用例也要跑**：每个用例都用「自己租户 + 自己资源」再打一遍，确认 **200**，排除误杀。
- **employee token 必须用真实员工 id**：伪造 id 会让"应该通过"的正向用例 401。
- **admin 的 `?tenant_id=` 是设计放行的**：admin 跨租户读不是 bug，是设计（现在有审计兜底）；上面所有"期望 403"的用例只对 employee 成立。
- 测试完删除 `tmp_mint_token.go`，不要把带 secret 读取逻辑的工具留在仓库。
