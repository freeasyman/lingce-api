# 合规卫士提示词表与规则表说明

## 目的

本文记录沟通合规运行时使用的提示词表和规则表，避免后续调试时反复查找表名。

## 提示词

### 表名

`recording_analysis_prompts`

### 当前沟通合规提示词编码

`compliance_check_v1`

### 运行时用途

合规 API 根据提示词编码读取全局提示词：

- `system_prompt`
- `user_prompt_template`
- `version`
- `is_active`

如果当前租户在 `recording_analysis_tenant_configs` 中配置了启用的同编码覆盖，则按租户配置覆盖全局提示词。

查询示例：

```sql
SELECT
    id,
    code,
    version,
    is_active,
    system_prompt,
    user_prompt_template
FROM recording_analysis_prompts
WHERE code = 'compliance_check_v1';
```

## 规则

### 表名

`compliance_rules`

### 运行时筛选条件

沟通合规 API 按以下条件读取规则：

- `subject = 'communication'`
- `status = 'published'`
- `is_enabled = true`
- `scene_codes` 包含当前沟通场景
- `role_codes` 包含当前角色
- 同一 `version`

规则完整内容保存在 `definition` JSONB 字段中，规则名称和判断标准同时保存在：

- `rule_name`
- `judgment_standard`

查询医生沟通规则：

```sql
SELECT
    id,
    rule_code,
    rule_name,
    version,
    status,
    is_enabled,
    scene_codes,
    role_codes,
    judgment_standard,
    definition
FROM compliance_rules
WHERE subject = 'communication'
  AND status = 'published'
  AND is_enabled = true
  AND scene_codes @> '["communication.doctor.outpatient"]'::jsonb
  AND role_codes @> '["doctor"]'::jsonb
ORDER BY id;
```

查询咨询师沟通规则：

```sql
SELECT
    id,
    rule_code,
    rule_name,
    version,
    status,
    is_enabled,
    scene_codes,
    role_codes,
    judgment_standard,
    definition
FROM compliance_rules
WHERE subject = 'communication'
  AND status = 'published'
  AND is_enabled = true
  AND scene_codes @> '["communication.consultant.consultation"]'::jsonb
  AND role_codes @> '["consultant"]'::jsonb
ORDER BY id;
```

## 相关结果表

本次检查结果写入：

`compliance_check_runs`

该表不是提示词表或规则表，主要保存：

- 本次输入和版本摘要；
- 使用的提示词版本、规则版本和模型配置；
- 检查状态；
- 命中的规则编码；
- 大模型原始响应；
- 格式化后的结果 JSON；
- 失败信息。

## 维护边界

- 提示词内容维护在 `recording_analysis_prompts`，不从 Worker 代码或本地文本文件读取。
- 沟通规则维护在 `compliance_rules`，不从旧的 `guard_rule_*` 表读取。
- `compliance_check_runs` 只保存检查执行记录，不反向作为提示词或规则来源。

真正供待核查和已核查页面读取的业务发现表是：

`compliance_findings`

`compliance_check_runs` 中 `finding_count = 0` 时只代表本次检查完成且没有发现，不会生成
`compliance_findings` 记录，也不应进入待核查列表。
