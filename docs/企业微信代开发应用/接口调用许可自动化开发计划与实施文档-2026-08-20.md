# 企业微信代开发应用接口调用许可自动化

## 1. 目标

解决客户企业新增员工后，员工首次进入代开发应用时看到企业微信原生错误：

> 应用无法使用，应用服务商还没有在企业微信为你开通接口调用许可。

正式链路必须满足：

1. 客户管理员只负责扫码安装应用、设置应用可见范围。
2. 系统在收到客户安装授权后，自动为该客户企业开启许可自动激活。
3. 员工首次访问应用或系统向员工发送应用消息时，由企业微信自动激活可用许可。
4. 服务商系统接收并记录 `auto_activate` 事件，运营人员可以确认激活是否发生。
5. 企业微信暂时没有完成激活时，员工端显示友好提示，不显示企业微信原始 48002 错误。
6. 许可不足、服务商未购买许可等不可由代码解决的条件，必须在运营端明确显示。

## 2. 关键边界

- 本次只处理企业微信代开发应用，不引入标准应用或其他模式。
- `suite_access_token` 只用于代开发模板和客户授权链路。
- `corp_access_token` 只用于客户企业应用登录、发消息等企业接口。
- `provider_access_token` 专门用于接口调用许可接口，不能与前两者混用。
- 代码不能凭空创建许可。服务商必须在企业微信服务商后台具备可用的接口调用许可或试用额度。
- 不通过登录失败推断“重装”或删除绑定，不手工补员工绑定数据。

## 3. 现状审计结论

### 3.1 已有能力

- 代开发安装回调已保存 `corp_id`、永久授权码和 `agent_id`。
- 代开发登录已通过 `suite_ticket -> suite_access_token -> get_corp_token` 获取客户企业凭证。
- 现有 `wecom_runtime_state` 已有 `provider_access_token` 和过期时间字段。
- 现有 `wecom_event_logs` 可以保存系统事件原文。
- 现有员工登录错误由 `/api/v1/wecom/delegated-app/oauth/login` 返回。

### 3.2 缺失根因

- 安装成功后没有调用：

  `POST /cgi-bin/license/set_auto_active_status?provider_access_token=...`

- 系统事件回调只保存为笼统的 `enterprise_callback`，没有识别并记录 `auto_activate`。
- OAuth 登录接口把企业微信的 48002 原文直接返回给 H5，导致客户员工看到企业微信内部错误。
- H5 没有针对“许可正在自动开通/许可不足”的业务提示。

## 4. 实施方案

### 阶段 A：服务商凭证和许可接口

1. 使用配置中的服务商 `corp_id` 与 `secret` 获取 `provider_access_token`。
2. 将凭证写入现有 `wecom_runtime_state`，按过期时间复用。
3. 新增代开发客户端方法：
   - 设置客户企业自动激活状态。
   - 查询客户企业自动激活状态。
4. 安装授权成功后，自动调用设置接口开启自动激活。
5. OPS 健康检查增加“许可自动激活”状态。

### 阶段 B：系统事件

1. 解析服务商系统事件中的 `InfoType`。
2. 对 `auto_activate` 事件保存可检索的事件日志，保留原始 XML。
3. 记录客户企业、员工 UserID、激活场景和许可到期时间的可读日志信息。
4. 不新增许可表，不复制激活码，不把激活码写入业务表。

### 阶段 C：员工端友好错误

1. API 将企业微信错误码 `48002`、`701000` 等许可未开通类错误映射为稳定业务码。
2. API 日志保留原始错误，HTTP 响应不向员工暴露企业微信内部文本。
3. H5 显示：
   - “应用正在开通，请稍后重新进入。”
   - 若确认服务商没有可用许可，显示“应用许可暂未开通，请联系管理员。”
4. 不自动循环刷新、不反复重启 OAuth、不要求员工输入灵策账号密码。

### 阶段 D：回归验证

1. 服务商后台确认服务商凭证可用，并确认接口调用许可能力已开通。
2. OPS 中确认模板回调已接通、客户实例已绑定、许可自动激活为“已开启”。
3. 用一个未激活但在应用可见范围内的新员工进入应用。
4. 检查：
   - 员工端不出现 48002 原文。
   - 代开发系统事件回调出现 `auto_activate`。
   - 员工随后重新进入应用可正常登录。
5. 再测试发送应用消息触发自动激活的场景。
6. 测试无可用许可场景，确认员工端和 OPS 提示清晰。

## 5. 需要运营人员在企业微信后台做的最少操作

只需要完成以下事项：

1. 在服务商后台确认“接口调用许可”能力已开通，并购买或启用足够的基础许可账号。
2. 保持代开发模板的系统事件接收 URL 指向系统提供的正式回调地址。
3. 客户管理员只需扫码安装，并把需要使用应用的成员加入应用可见范围。

不需要运营人员逐个复制激活码，也不需要客户员工填写 Corp ID、Agent ID、手机号或密码。

## 6. 验收标准

- 新安装客户实例自动开启许可自动激活。
- 新员工进入应用后，许可充足时无需人工干预即可登录。
- 许可不足时，员工只看到业务提示，运营端能看到可执行原因。
- 代开发登录、消息发送和许可接口使用的凭证链路明确分离。
- 只提交本次涉及文件，不提交其他 agent 的未提交改动。
