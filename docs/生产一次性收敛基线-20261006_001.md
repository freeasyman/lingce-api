# 生产一次性收敛基线：20261006_001

## 目的

把开发环境截至 2026-10-07 审计确认的目标结构和正式配置一次性收敛到生产。它不重放开发历史迁移，不复制开发运行数据，也不删除生产已有表、字段或数据。

正式脚本：`internal/store/convergence/20261006_001.sql`

## 已包含

- EMR、随访、合规、权限相关目标表和可重复的增量列扩展；
- 6 个正式 EMR 模板、字段及模板字段关系；
- `2026-10-04-v2` 的 43 条正式门诊病历质检规则；
- 门诊病历质量评分标准；
- 平台正式提示词和模型参数，不写入 API Key；
- 管理员默认能力点，不包含已撤销的 `record.export`；
- 仅把已有持久化的“已完成/待人工复核”评分投影到病历当前评分字段，未评分病历保持 `NULL`。

## 明确不包含

- 开发库中的病历、录音、质检执行记录、评分历史和租户私有配置；
- 密钥、密码、API Key；
- ICD-10 目录数据。目录必须从受控正式文件单独导入，不能复制开发运行数据；
- 首次收敛阶段对已有表强加主键、唯一约束或外键。结构合同和约束收紧应在生产数据核验后的后续 contract 迁移中完成。

## 执行前置条件

1. 完成生产数据库备份或确认可恢复点；
2. 在临时生产快照库执行同一脚本并完成关键表、正式规则数量和评分字段核验；
3. 确认生产网络可解析数据库域名；
4. 准备受控 ICD-10 导入文件和单独导入窗口；
5. 确认 `internal/store/convergence/20261006_001.sql` 的 checksum 与发布包一致。

## 执行顺序

由开发中心显式执行，Agent 不启动 API 或 Worker：

```bash
./bin/lingce-api --config ./configs/prod-baseline.toml --converge-only
./bin/lingce-api --config ./configs/prod-baseline.toml --verify-convergence
```

验证通过后，再用 `prod-baseline.toml` 启动 API。Worker 在 API 健康检查后单独发布和启动。

## ICD-10 单独步骤

先导入受控正式目录，再执行目录行数、唯一性、启用状态和抽样名称核验。导入失败不得修改或重跑收敛脚本；应修复导入批次后单独重试。

## 当前发布结论

代码、收敛脚本、配置示例已准备，`check_migrations.sh` 和相关 Go 测试通过。由于当前环境无法解析生产数据库域名，尚未完成临时库演练和生产执行，因此现在只能标记为“具备发布准备条件”，不能宣称生产已发布。
