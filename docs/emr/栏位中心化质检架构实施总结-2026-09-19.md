# 栏位中心化质检架构实施工作总结

## 工作目标
将电子病历质检规则从旧架构(基于`emr_quality_rules`表和模板绑定)迁移到栏位中心化架构(规则存储在`emr_fields.quality_rules` JSONB字段中)。

## 已完成工作

### 1. 后端核心架构文件创建
已在 `/Users/yiliiang/Documents/lingce-api/internal/emrcheck/` 创建以下新文件:

#### 核心加载器和注册器
- **`field_quality_loader.go`**: 栏位质量规则加载器
  - `FieldQualityLoader`: 从数据库加载模板的栏位质量规则
  - `LoadFieldQualityRules()`: 查询`emr_fields.quality_rules`
  - `FlattenQualityRules()`: 将栏位规则展平为可执行列表

- **`field_executor_registry.go`**: 执行器注册系统
  - `ExecutorRegistry`: 管理程序判断规则执行器的注册表
  - `Execute()`: 根据规则的`executor`字段动态调用对应函数
  - `registerAllExecutors()`: 注册所有执行器

#### 执行器实现文件(按栏位分组)
- **`executors_chief_complaint.go`**: 主诉执行器(7个)
- **`executors_present_illness.go`**: 现病史执行器(12个)
- **`executors_history.go`**: 病史类执行器(10个) - 既往史、个人史、过敏史、家族史
- **`executors_exam.go`**: 检查类执行器(8个) - 体格检查、辅助检查
- **`executors_diagnosis_treatment.go`**: 诊疗类执行器(12个) - 诊断、处方、处置
- **`executors_advice_followup.go`**: 医嘱与随访执行器(5个)
- **`executors_gynecology.go`**: 妇科专用执行器(12个)
- **`executors_pediatric.go`**: 儿科专用执行器(10个)
- **`executors_oral.go`**: 口腔科专用执行器(8个)
- **`executors_tcm.go`**: 中医专用执行器(18个)

**当前程序规则为16条**,其余92条为大模型规则或后续语义判断规则。程序执行器只覆盖能够确定性判断的规则；需要对照录音、生成依据或进行语义理解的规则不注册为程序执行器。

## 技术架构说明

### 数据流程
```
HTTP请求
  → Handler
  → Service.PreviewFieldCentricProgram()
  → FieldQualityLoader.LoadFieldQualityRules()
    → 查询数据库获取栏位+规则
  → ExecutorRegistry.Execute()
    → 调用具体执行器函数
  → 返回CheckResult[]
```

### 执行器设计模式
```go
type ProgramExecutor func(rule ExecutableRule, data checkContext) evaluatedResult
```
- 每个执行器是独立函数
- 通过注册表动态路由
- 统一的输入输出接口

### 规则来源
- **程序判断规则**: 硬编码逻辑(非空、长度、格式等)
- **LLM判断规则**: 需要语义理解(一致性、推断、真实性等)。例如“中药处方保留已知药材和用法信息”需要对照原始转写或生成依据，不能仅凭结构化处方字段确定判断。
