# 金句库数据来源说明（赢客专家）

> 本文档把「金句」的正确数据来源写死，防止再次用错数据源。
> 2026-11-23 定稿。此后金句库的改动必须与本文件一致。

## 一句话结论

金句库读的是 **产品分析里的现成金句字段**：

```text
recordings.analysis_result.content_seeds[].type = "golden_quote"
```

金句是产品分析（`consultant_conversion_analysis_v1` 等）输出里**独立的、专门的字段**，
不归 `quality_review` 管，也不是从质检分里“挑出来的句子”。

---

## 1. 数据模型：三个不同概念，不许混用

| 概念 | 字段位置 | 是什么 | 能当金句吗 |
|---|---|---|---|
| 金句 | `content_seeds[].type = "golden_quote"` | 专门的“金句片段”：说话人用了精彩的比喻、类比、金句 | ✅ 唯一正统来源 |
| 内容素材 | `content_seeds[].type = aha_moment / practical_qa / concern_handling / relatable_scene` | 公域内容素材，里面有 `key_quotes` 原话 | 本身不是金句，但 `key_quotes` 里的咨询师原话可以按精彩表达规则补充 |
| 质检 | `quality_review.items[]` / `consultation_analyses.analysis.quality_review.dimensions[]` | 对沟通各环节的打分 + 点评证据 | ❌ 不是金句。环节分高 ≠ 这句话精彩 |

### golden_quote 的字段结构

```json
{
  "type": "golden_quote",
  "topic": "做近视手术时，医生最怕你做什么？",
  "key_quotes": [
    { "text": "你不找他，就是上课怎么发呆的……就是发呆。", "speaker": "咨询师", "time": "00:01:50" },
    { "text": "客户原话……", "speaker": "客户" }
  ],
  "summary": "将复杂的术中配合简化为『像上课发呆一样保持不动』，极具传播力……",
  "content_angle": "用『发呆』这个生活化指令替代专业术语",
  "patient_concern": "担心自己术中配合不好影响效果",
  "stage": "帮人了解",
  "viral_potential": "高"
}
```

### 提示词里的定义（现成，不新写）

```text
prompt code: consultant_conversion_analysis_v1
“golden_quote：咨询中出现了精彩比喻、类比、金句，适合做短视频钩子或海报文案。”
```

## 2. 数据在哪里生成、保存、读取

### 生成

```text
worker 基础分析
→ 按角色路由到产品分析（consultant_conversion_analysis_v1 / doctor_conversion_analysis_v1 / therapist_conversion_analysis_v1）
→ 输出 content_seeds，其中 type=golden_quote 就是金句
```

### 保存（分析结果）

```text
recordings.analysis_result（jsonb）
└─ content_seeds[]   ← 金句在这里
└─ quality_review    ← 质检在这里（与金句无关）
```

### 金句库落库（审核/收录表）

```text
benchmark_clips
  clip_text      原话
  context_text   客户上下文
  use_when       什么时候用（stage）
  ai_comment     为什么有效（summary）
  dimension      golden_quote·N 或 quote·N
  source         auto_v2
  status         accepted（现成金句直接入库）/ pending / rejected
  role_code      consultant / doctor / therapist
```

### 读取接口

```text
GET    /recordings/benchmark-clips?status=accepted|pending|rejected
POST   /recordings/benchmark-clips/{id}/actions/accept
POST   /recordings/benchmark-clips/{id}/actions/reject
DELETE /recordings/benchmark-clips/actions/clear-rejected
```

前端：`apps/deal-v2` 金句库页（候选卡 / 库 / 回收站 / 恢复 / 清空回收站）。

## 3. 当前生成规则（代码口径，2026-11-23 起）

`internal/recording/service.go` → `GenerateBenchmarkCandidates`：

```text
1. 扫 recordings.analysis_result.content_seeds
2. 只取 key_quotes 里 speaker=咨询师/医生/治疗师 的原话
3. 收录条件（满足其一）：
   a. 该 seed 的 type 就是 golden_quote
   b. 原话命中精彩表达标记：
      就像|好像|相当于|好比|比喻|一样|口袋|剪子|磨薄|回弹|发呆|愣神|
      导航|胶水|气球|牛仔裤|大油|锁水|高跟鞋|虚焦|头发丝|玻璃上|长痘|
      灯在晃|8到10秒|9秒|26秒|5%|隐形眼镜|高铁
      且不含日常医嘱（少吃|多喝水|少熬夜|少玩|早睡|多运动|别揉|保持清洁|多吃）
4. 每个 seed 只收第一条命中的咨询师原话（一个录音可能多条）
5. 直接以 accepted 入库（现成工作成果，不捂着）
6. 不读 quality_review，不读 consultation_analyses.analysis.evidence/quality_review
7. 不调用 LLM，不做新分析；纯读取现成字段 + 规则过滤
```

角色覆盖：consultant / doctor / therapist 三种录音都扫。

## 4. 今天犯过的错（禁止再犯）

| # | 错误做法 | 正确做法 |
|---|---|---|
| 1 | 从 `quality_review.dimensions[].evidence` 挑 score>=4 的句子当金句 | 环节分高不等于金句，禁止 |
| 2 | 读 `recording_content_seeds` / 全量 content_seeds 把内容中心素材当金句 | 只认 `content_seeds.type=golden_quote` 与 key_quotes 原话 |
| 3 | 自己发明新的“金句字段 / 新提示词 / 新分析步骤” | 字段是现成的，不许重新发明 |
| 4 | 误把 `deal_expert_consultation_analysis`（决定卡）当成金句来源 | 决定卡没有金句字段 |
| 5 | 金句候选按时间窗口（60/180/365 天）过滤，把已有成果藏着 | 全量物化，不设时间窗口 |
| 6 | 为了“修旧”而删除现有的候选/已收录数据 | 不删数据；垃圾数据单独确认后再处理 |
| 7 | 只扫 consultant，漏掉医生/治疗师录音的金句 | 三种角色都要扫 |

而不是普通流程话、报价说明、日常医嘱。
