## 1. 判定口径

1. **会不会烧钱**：是否直接调 `llmgateway`（文本/视觉/生图/检索）、是否经 worker 触发 ASR/LLM 分析、
   是否调用会写入 `gateway_call_records` 的网关。
2. **预检**：调用模型/worker 之前是否走 `CheckQuota`（或其封装 `ensure*Quota`）。
3. **扣量**：交付成功后是否走 `Deduct`，且是否按交付判定（空交付不扣、幂等键防重）。
4. **N/A**：设计上不属于六产品计量交付单元，或属于基础链路/内部运维/调试接口。
   **不硬补**，但写明“会烧钱”与不扣原因。

## 4. 纯读/导出接口的误伤检查

对所有产品包内的 GET/导出路由做了 `CheckQuota` / `ensure*Quota` 调用点反查：

- 计费预检只出现在 8 个交付入口：听写病历草稿/质控、赢客分析、客户总监截图/动作/录音/方案、
  随访生成、合规检查、获客先锋洞察/AI 可见性/文稿/图片。
- `GET /api/v1/emr/records*`、`GET /api/v1/recordings*`、`GET /api/v1/patient-operations*`、
  `GET /api/v1/content-*`（含 `export-docx` / `export-images-zip` / `export`）、
  `GET /api/v1/deal-expert/outcomes/export.xlsx`、`GET /api/v1/compliance*`、
  `GET /api/v1/tenants/{id}/entitlements|entitlement-ledger` 均**没有**额度预检。
- 唯一发现的误伤：`POST /api/v1/patient-operations/screenshots/analyze` 在命中已有成功结果时
  仍先做 shot 预检，导致额度用完的客户无法查看历史截图。**已修**：预检下沉到真正要调模型的
  首次分析/失败重试分支，复用分支直接返回（`service.go:1093,1105`）。

## 6. 统一拒绝文案与错误码

代码位置：`internal/billing/gate.go`。

| 情况 | 错误码 | 文案 | HTTP（产品侧 / 内部扣量接口） |
|---|---|---|---|
| 服务已到期 | `SUBSCRIPTION_EXPIRED` | 服务已到期，请联系您的专属顾问 | 409 / 409 |
| 服务已暂停 | `SUBSCRIPTION_PAUSED` | 服务已暂停，请联系您的专属顾问 | 409 / 409 |
| 额度不足 | `INSUFFICIENT_ENTITLEMENT` | 当前额度已用完，请联系客服加购增量包 | 402 / 409（内部接口保持既有 409 契约） |

改动点：

- `billing.GetSubscriptionState` 增加到期判定（读取 `tenant_subscriptions` 最新一条服务期；
  暂停优先），`subscriptionGuard` 映射 `ErrSubscriptionPaused` / `ErrSubscriptionExpired`。
- 六个产品的 `ensure*Quota`：暂停/到期不再 fail-open，统一返回计费层错误，由 HTTP 层
  `billing.GateRejection` 映射成客户口径；计费自身故障仍 fail-open。
- 产品侧原错误码 `EMR_QUOTA_EXHAUSTED` / `CONTENT_QUOTA_EXHAUSTED` /
  `PATIENT_OPS_QUOTA_EXHAUSTED` / `COMPLIANCE_QUOTA_EXHAUSTED` 全部收敛为
  `INSUFFICIENT_ENTITLEMENT`；原文案「额度已用完，请及时联系客服，加购增量包」统一为
  「当前额度已用完，请联系客服加购增量包」。
- 随访异步 run 的 `last_error_code`：额度不足 `QUOTA_EXHAUSTED`、暂停 `SUBSCRIPTION_PAUSED`、
  到期 `SUBSCRIPTION_EXPIRED`，`last_error_message` 为客户口径。
- 运营端保留内部口径：`/api/v1/ops/billing/institutions/{id}/suspend` 等运营路由仍返回
  「该机构服务已暂停，请联系运营恢复」（`internal/billing/institution_handler.go:1184`），
  这是运营端自己的提示，符合要求。
- 清掉客户侧残留的「联系管理员」：权限错误改为「请联系机构管理员」，质检配置错误改为
  「请联系您的专属顾问」。全仓非测试代码已无「联系管理员」；「请联系运营」只出现在运营端。

   计划摘要；客户总监的产品关键词建议；合规卫士调试接口。设计只定义了 4 个获客先锋交付单元，

2. **多图异步生图预检只按 1 张**：`generate-images-async` / 分镜图预检 `shot 1`，实际逐图扣量；
   低余额时会先生成、后扣量失败（欠扣）。建议按 `len(prompts)`/缺失图位数预检。
3. **实时转写纠错（WebSocket）按段调用 LLM**：当前计为 ASR 基础链路、不计量；如果实际成本高，
   需要重新评估是否纳入听写病历 hour。
4. **质量轮次无预检的历史路径已补**，但 `emrquality.Execute` 内部仍有 3 次模型调用；
   余额恰好只够 1 轮时会扣成负数并暂停，符合现有“最后一笔可超扣”规则。
5. **`/api/v1/compliance/debug/analyze-text`** 只校验 JWT、不校验 claims 租户与权限，
   且可自由调用 LLM；建议生产环境关闭或加 admin + 租户绑定。
6. **运营端暂停文案**仍是内部口径（按要求保留）；如果未来该接口被客户侧复用，需要换成
   `billing.GateRejection` 的客户文案。
7. **实验增量草稿的预检不识别“已扣过”**：整份病历已由 worker 正式生成并扣过
   `emr:record:<id>:draft` 后，实验页的增量请求仍会先 `CheckQuota(record+hour)`；若此时额度刚好为 0，
   增量更新会被拦（虽然扣量本身是幂等的、不会重复扣）。要彻底解决需要给计费层补一个
   “幂等键是否已扣”的只读查询；本次未扩大接口面。
