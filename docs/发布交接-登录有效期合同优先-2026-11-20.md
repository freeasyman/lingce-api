# 发布交接：登录有效期改为「合同优先、老表兜底」（2026-11-20）

> ⚠️ **先读第三节。不要直接拿本文的二进制覆盖线上。**

## 一、背景

北京茗视光眼科（机构 4，员工 18583385921 杜玉芹）登录桌面端被拒，返回 401：
`TENANT_INACTIVE / tenant subscription expired`。

原因：桌面端/机构端走 `/auth/login/institution`（老产品入口），只校验 `tenants.valid_to`；
该机构 `valid_to = 2026-07-09`（已过期），但新合同 `subscription_periods` 是
`2026-11-19 ~ 2026-12-18`（active）。即「续费只写了合同表，没同步老有效期」。

## 二、改动内容（5 个文件，+57/−6）

### 1. `internal/contract/contract.go` — 新增 `HasPeriods()`

判断租户是否已有服务期记录，作为「合同优先 / 老表兜底」的分叉点。

### 2. `internal/auth/service.go` — `checkEntryAccess()`

```diff
+	// 暂停中的机构一律拒绝（与计费闸门/中间件同口径）。
+	if tenant.PausedAt != nil {
+		return newUnauthorizedError("SUBSCRIPTION_PAUSED", "该机构服务已暂停，请联系运营恢复")
+	}
 	if entry == auth.EntryPortal { ... 合同判定 ... }
-	// 老产品：维持原判断（tenants.valid_to）。
+	// 老产品：合同优先、老表兜底。
+	hasPeriods := contract.HasPeriods(...)
+	if hasPeriods {
+		ok := contract.CanAccess(...)
+		if !ok { return TENANT_INACTIVE }
+		return nil
+	}
 	if tenant.ValidTo != nil && tenant.ValidTo.Before(now) {
 		return newUnauthorizedError("TENANT_INACTIVE", "tenant subscription expired")
 	}
```

> **边界必须保留**：是「有没有服务期记录」决定走哪套口径。
> 有记录但已过期 → 拒绝；**不能**因为 `valid_to` 还写着未来日期就放行。

### 3. `internal/auth/model.go` + `store.go`

`Tenant` 增加 `PausedAt` 字段，`GetTenantByID` 多查一列 `paused_at`。

### 4. `internal/middleware/auth.go` — 老产品分支同口径

在原有那条 SQL 里一次算完（不增加往返）：

```sql
(t.paused_at IS NOT NULL) AS tenant_paused,
CASE
  WHEN EXISTS (SELECT 1 FROM subscription_periods sp WHERE sp.tenant_id = t.id)
    THEN EXISTS (SELECT 1 FROM subscription_periods sp
                 WHERE sp.tenant_id = t.id AND sp.status = 'active'
                   AND sp.started_on <= CURRENT_DATE AND sp.expired_on >= CURRENT_DATE)
  ELSE COALESCE(t.valid_to, t.service_expired_on) > NOW()
END AS tenant_allowed
```

判定改为 `if tenantPaused || !tenantAllowed { return false }`。

> 登录改了、中间件不改，结果就是「登录成功但之后每个请求 401」，更难查。**两处必须一起合。**

## 五、验证

### 1. 静态验证（上线前，生产库只读）

```sql
-- 期望：茗视光 allowed = true；纯老客户（无合同、未过期）allowed = true；已过期老客户 allowed = false
SELECT t.id, t.name,
       (t.paused_at IS NOT NULL) AS paused,
       EXISTS (SELECT 1 FROM subscription_periods sp WHERE sp.tenant_id=t.id) AS has_periods,
       CASE
         WHEN EXISTS (SELECT 1 FROM subscription_periods sp WHERE sp.tenant_id=t.id)
           THEN EXISTS (SELECT 1 FROM subscription_periods sp WHERE sp.tenant_id=t.id
                        AND sp.status='active' AND sp.started_on<=CURRENT_DATE AND sp.expired_on>=CURRENT_DATE)
         ELSE COALESCE(t.valid_to, t.service_expired_on) > NOW()
       END AS allowed
FROM tenants t WHERE t.id IN (4,5,13,14,16) ORDER BY t.id;
```

### 2. 登录验证

- 机构 4 员工 `18583385921`（杜玉芹）用桌面端登录 → 应成功；
- 纯老客户机构（如 5 大连百川中医医院）员工登录 → 行为不变；
- 已过期机构（13/14/16）员工登录 → 仍被拒，文案「机构服务已到期」；
- 暂停机构 → 返回 `SUBSCRIPTION_PAUSED`「该机构服务已暂停，请联系运营恢复」。

确认**中间件**没有把请求拦掉（这是最容易漏的一处）。
