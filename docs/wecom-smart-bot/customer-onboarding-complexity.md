# 客户企业创建并接入智能机器人的复杂度评估

## 结论

相较于自建应用/代开发应用，智能机器人接入明显更轻量，但仍不是“客户只填一个 Webhook”这么简单。客户至少需要一名企业微信管理员完成机器人创建、可见范围配置，并把 Bot ID 和 Secret 通过安全方式交给灵策。员工还需要在机器人可见范围内，且主动与机器人建立会话后，灵策才能稳定向该会话主动推送（这一点以官方 CLI 当前说明为准，需真实 Bot 再验证）。

综合评估：

- **技术配置复杂度：低到中**
- **客户管理员操作复杂度：低**
- **员工首次使用复杂度：低到中**
- **SaaS 多租户交付复杂度：中**

## 客户侧步骤

1. 管理员进入企业微信管理后台的智能机器人入口。
2. 创建 API 模式智能机器人，并选择长连接接入（若后台提供该选项）。
3. 设置机器人名称、头像和可见范围。
4. 复制 Bot ID 和 Secret，提交到灵策接入向导。
5. 在灵策中完成连接测试。
6. 引导员工在可见范围内私聊机器人，或把机器人加入需要使用的内部群并 @ 它。
7. 用一条测试消息验证自动回复，再验证任务提醒/分析结果推送。

客户不需要配置公网回调域名、备案域名、固定公网 IP，也不需要提供 CorpID、AgentID、应用 Secret 或配置传统应用回调 URL。

## 灵策侧必须承担的工作

- 加密保存每个租户的 Bot ID/Secret，不在前端再次展示 Secret；
- 建立并维护长连接，处理心跳、断线重连和连接状态；
- 保证同一个 Bot 同时只有一条有效连接；
- 为客户提供凭证校验和连接状态页；
- 提供可见范围、会话建立和主动推送的测试结果；
- 记录消息发送失败原因（未建立会话、权限、限流、凭证失效）；
- 支持客户重置 Secret 后重新绑定。

## 复杂度和风险来源

### 客户侧

- 管理员需要找到正确的后台入口；
- 可见范围配置错误会导致员工找不到机器人；
- Secret 属于高敏感凭证，不能通过聊天工具明文传递；
- 员工需要主动打开/私聊机器人，不能只创建后期待所有人自动收到消息；
- 群场景还需要把机器人加入目标群并使用 @。

### 灵策侧

- 单 Bot 单长连接导致部署不能简单按无状态服务扩容；
- 多租户需要连接租约、故障接管和密钥隔离；
- 主动发送范围可能受“最近会话”约束，不能先按任意员工 userid 承诺全量触达；
- 企业微信协议和 CLI 能力可能持续变化，需保留原始错误和能力探测。

## 与自建应用的客户操作对比

| 项目 | 智能机器人 | 自建/代开发应用 |
|---|---|---|
| 客户是否需创建对象 | 创建一个机器人 | 创建应用并配置应用参数 |
| 主要凭证 | Bot ID + Secret | CorpID、AgentID、AppSecret 等 |
| 公网回调 | 长连接模式通常不需要 | 通常需要配置回调 URL |
| 可见范围 | 机器人可见成员/群 | 应用可见范围及应用权限 |
| 员工聊天 | 私聊、群内 @ | 默认不是普通聊天监听 |
| 灵策主动消息 | 已建立会话的单聊/群聊可行 | 应用消息能力更成熟 |
| 客户外部联系人 | 不支持 | 可组合客户联系能力 |

## 产品化接入向导建议

向导只保留四步：

1. **创建机器人**：展示后台入口和截图说明；
2. **填写凭证**：Bot ID、Secret，一次性提交并加密保存；
3. **配置使用范围**：提醒管理员加入成员和群；
4. **发送测试消息**：员工回复“测试”，灵策确认收发链路。

向导中必须明确说明：该机器人服务企业内部员工，不支持外部联系人；主动推送以已建立的机器人会话为准，直到真实 Bot 验证确认更宽的 userid 发送能力。
