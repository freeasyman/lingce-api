## 已确认

官方 `wecom-cli` README 明确写有“机器人主动通知”，消息技能明确支持向机器人会话发送消息，目标会话包含：

- 单聊
- 群聊

支持的消息类型包括 Markdown、图片、文件、语音和视频。README 将能力描述为“向机器人最近对话过的单聊/群聊主动推送消息”。因此，主动推送任务提醒和分析结果在产品方向上成立。

## 关键限制（以可审计的官方 CLI 说明为准）

`wecomcli-message/SKILL.md` 对发送范围有比“可见范围内任意成员”更严格的约束：

1. 可以给授权人发送消息。
2. 可以给机器人最近有消息往来的单聊或群聊发送消息。
3. 发送其他对象前，必须先调用 `message aibot sessions list`，目标必须来自本次返回的会话列表。
4. 不允许用外部传入或自行构造的 `chat_id` 绕过会话范围。
5. 当前文档没有证明可以仅凭任意员工 `userid` 向一个从未与机器人建立会话的员工发起私聊。

这意味着“主动发送”已确认，但“向可见范围内任意员工 userid 主动发送”目前不能仅凭已归档材料确认。生产产品承诺应先按真实 Bot 做黑盒测试，特别测试：

- 员工从未私聊机器人时，是否能仅凭 userid 主动发起消息；
- 员工曾私聊机器人后，是否可持续主动推送；
- 机器人所在群是否必须已有消息往来；
- 可见范围是否等同于可发送范围。

## 对灵策目标的结论

### 可以作为 MVP

- 员工私聊机器人，灵策接收并自动回复；
- 群内 @机器人，灵策接收并自动回复；
- 对已经建立机器人会话的员工或群发送任务提醒、分析结果；
- 发送 Markdown、图片、文件等通知。

### 暂不能直接承诺

- 只配置可见范围后，就能向该范围内所有员工任意主动发起私聊；
- 向没有与机器人建立会话的员工发送第一条消息；
- 向外部联系人、患者或客户联系用户发送消息。

## 实施建议

POC 先复用 `wecom-cli message aibot sessions list/send` 验证真实客户 Bot 的会话范围，再决定 Go Transport 的 `aibot_send_msg` 是否设计为 `userid` 目标、`chatid` 目标，或只接受已授权会话 ID。不要根据二手描述直接把“可见范围”实现成“任意员工可主动触达”。
