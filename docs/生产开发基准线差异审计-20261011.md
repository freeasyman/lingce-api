## 表级差异

开发独有的 11 张表：

- `compliance_check_items`
- `compliance_check_item_sources`
- `compliance_check_item_process_records`
- `followup_task_audits`
- `guard_rule_catalog_versions`
- `guard_rule_set_rule_versions`
- `guard_rule_set_versions`
- `guard_rule_versions`
- `recording_prompt_debug_annotations`
- `inst_employee_roles_bak`
- `inst_role_menus_bak`

其中两个 `inst_*_bak` 是迁移备份对象，不能进入生产基准线；`recording_prompt_debug_annotations` 是调试数据表，除非产品明确要求，不进入生产基准线。前 8 张是当前合规/随访业务模型的一部分，需要经过正式规则和权限审计后纳入收敛脚本。

生产独有的表：

- `api_schema_baselines`：生产 baseline 账本，必须保留；
- `inst_employee_roles`、`inst_role_menus`：旧权限兼容表，暂不删除；
- `wecom_suite_tickets`：生产专有企业微信数据，必须保留。

## 字段差异

开发相对生产多 173 个字段，主要集中在随访任务执行闭环和 EMR/合规模型。代表性字段包括：

- `recording_tasks.encounter_id`、`time_basis`、`escalation_status`、`escalation_resolution`；
- `recording_tasks.patient_age`、`patient_gender`、`patient_replied`、`revisit_attended`；
- `recording_tasks.phone_script`、`wechat_content`、`execution_result`、`returned_at`、`returned_by`；
- `recording_tasks.generation_source`、`generation_prompt_version`、`generation_model`。

这些字段应采用 Expand / Backfill / Verify 顺序，全部先允许空值，不能在第一次收敛时直接加严格约束。

## 数据边界

新 baseline 可以包含：

- 表、列、索引和非破坏性默认值；
- 平台正式提示词、规则、模板、评分标准和权限种子；
- 可重复且有影响行数记录的回填；
- baseline 版本和 checksum 账本。

新 baseline 不得包含：

- 开发录音、病历、分析运行记录和测试租户数据；
- API Key、密码、OAuth secret 和任何密钥；
- `*_bak` 备份表和调试标注数据；
- 删除生产旧表、删除生产数据或直接替换租户配置。

## 后续基线版本

建议新版本使用 `20261011_003`。生成前必须完成：

1. 对 8 张业务目标表逐表确认产品归属和权限边界；
2. 将 `recording_tasks` 字段扩展整理成可重复的 additive SQL；
3. 从开发种子中剔除 API Key 和租户私有配置；
4. 对 EMR 规则从 43 条到 96 条的变化确认正式版本和生效范围；
5. 在生产快照库演练并记录校验结果；
6. 更新 API 的 baseline 配置、内嵌 SQL 和 checksum；
7. 只读验证通过后再发布 API，不能在生产直接重放历史迁移。
