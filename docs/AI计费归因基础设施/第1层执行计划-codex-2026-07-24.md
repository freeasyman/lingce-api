## 0. 本层目标与边界

**目标**：把运营后台重做成一个**纯内部、只展示真实人民币成本**的成本分析工具，替换 codex 旧版"前端本地聚合"的错误实现。

**关键边界（不可违背）**：
1. **成本数据绝不给租户/客户看**。本层只做运营后台，不做任何租户侧/客户侧页面。
2. **全程真实人民币成本**，删除"估算点数"（`estimatePoints = cost*100`）的一切逻辑——点数是未来商业化的事，本层不碰。
3. **不做点数计费系统**（无 ai_billing_events、无充值扣费、无余额）。

**本层不涉及生产库写操作**（纯读聚合 + 前端），是常规后端接口 + 前端重构。

## 1. 核心架构改动：从"HTTP拉全量+内存聚合"改为"直连 SQL 聚合"

### 现状（错误实现，要推倒）
`internal/support/service.go` 的 `fetchAllAIUsageRecords`（line 809）通过 `llmClient.ListAuditRecords` **HTTP 翻页拉全量明细到内存**，再在 Go 里聚合；前端还二次拉 100 条本地算 Top-N/异常。数据量一大就慢且不准。

### 目标实现
`lingce-api` 与 `llm-gateway` **同连 `lingce_prod` 库**（已确认）。`support.Store` 已持有 `pgxpool.Pool`（`store.go:15-21`），已能直接查 `tenants` 表。
→ **所有聚合改为直接 SQL `GROUP BY` 查 `gateway_call_records`**，不再走 llmClient HTTP。

### 数据源表
`gateway_call_records`（35 列，第 0 层已迁移）。关键列：
```
tenant_id, business_domain, business_object_type, business_object_id,
billing_subject, recording_id, content_id, generation_task_id,
caller_module, function_type, provider, model_code, success,
input_tokens, output_tokens, total_tokens, total_cost,
usage_metadata(jsonb, 含 audio_duration_seconds), latency_ms, created_at
```

### 统一口径（所有聚合遵守）
- 成本/用量汇总默认 **`WHERE success = true`**。
- 失败调用只在 `anomalies` 接口单列，不计入成本汇总。
- 时间范围、租户、业务域、计费主题、模型、成功状态为通用筛选参数。
- 金额单位：人民币元，`total_cost` 直接求和，展示保留合适小数位。
- audio 时长：`(usage_metadata->>'audio_duration_seconds')::float`。

## 2. 后端任务（lingce-api / internal/support）

### 2.1 新建直连 SQL 聚合层：`store_aiusage.go`

在 `internal/support/` 新建 `store_aiusage.go`，所有方法挂在现有 `Store` 上（复用 `s.pool`）。统一构建 `WHERE` 子句的辅助函数：

```go
// buildUsageFilter 根据筛选参数拼 WHERE 条件与参数数组。
// 注意：用参数化查询（$1,$2...），禁止字符串拼接值，防注入。
func buildUsageFilter(f AIUsageFilter, startArgIdx int) (whereSQL string, args []any)
```

`AIUsageFilter` 字段：`TenantID *int64, BusinessDomain, BillingSubject, Provider, ModelCode string, Success *bool, StartDate, EndDate string`。

默认 `success=true`（除非 `anomalies` 显式要失败）。时间用 `created_at >= $x AND created_at < $y+1day`。

### 2.2 需实现的 Store 聚合方法（逐个给 SQL 骨架）

**(a) SummaryAggregate — KPI**
```sql
SELECT
  COUNT(*) FILTER (WHERE success) AS total_calls,
  COUNT(*) FILTER (WHERE NOT success) AS failed_calls,
  COALESCE(SUM(total_cost) FILTER (WHERE success),0) AS total_cost_cny,
  COALESCE(SUM(total_tokens) FILTER (WHERE success),0) AS total_tokens,
  COALESCE(SUM((usage_metadata->>'audio_duration_seconds')::float) FILTER (WHERE success),0) AS total_audio_seconds
FROM gateway_call_records
WHERE created_at >= $1 AND created_at < $2 {额外筛选};
-- success_rate = total_calls / (total_calls+failed_calls)
-- avg_cost_per_call = total_cost_cny / NULLIF(total_calls,0)
```

**(b) TrendDaily — 按天趋势**
```sql
SELECT date_trunc('day', created_at)::date AS day,
       COUNT(*) AS calls, COALESCE(SUM(total_cost),0) AS cost,
       COALESCE(SUM(total_tokens),0) AS tokens
FROM gateway_call_records
WHERE success AND created_at >= $1 AND created_at < $2 {筛选}
GROUP BY day ORDER BY day;
```

**(c) GroupByTenant / ByBusinessDomain / ByBillingSubject / ByModel**
通用分组模板（分组键分别为 tenant_id / business_domain / billing_subject / model_code）：
```sql
SELECT {groupKey} AS key,
       COUNT(*) AS call_count,
       COALESCE(SUM(total_cost),0) AS total_cost_cny,
       COALESCE(SUM(total_tokens),0) AS total_tokens,
       COALESCE(SUM((usage_metadata->>'audio_duration_seconds')::float),0) AS total_audio_seconds
FROM gateway_call_records
WHERE success AND created_at >= $1 AND created_at < $2 {筛选}
GROUP BY {groupKey} ORDER BY total_cost_cny DESC;
```
- ByTenant 需 JOIN/补 tenant_name（用现有 `GetTenantNameMap`）。

**(d) TopObjects — 高成本业务对象 Top-N（后端真 Top-N，替代前端本地算）**
按录音聚合（内容版把 recording_id 换 content_id、business_domain='content'）：
```sql
SELECT recording_id,
       MAX(tenant_id) AS tenant_id,
       COUNT(*) AS call_count,
       COALESCE(SUM(total_cost),0) AS total_cost_cny,
       COALESCE(SUM(total_tokens),0) AS total_tokens,
       COALESCE(SUM((usage_metadata->>'audio_duration_seconds')::float),0) AS total_audio_seconds,
       COUNT(*) FILTER (WHERE NOT success) AS failed_calls,
       MAX(created_at) AS last_at
FROM gateway_call_records
WHERE recording_id IS NOT NULL AND created_at >= $1 AND created_at < $2 {筛选}
GROUP BY recording_id
ORDER BY total_cost_cny DESC
LIMIT $N;
```

**(e) ObjectCostPage — 录音/内容成本大表（可翻页+排序+vs均值）★ 本层重点**
```sql
-- 主查询：分页 + 排序
SELECT g.recording_id, MAX(g.tenant_id) tenant_id,
       COUNT(*) call_count,
       COALESCE(SUM(g.total_cost),0) cost,
       COALESCE(SUM((g.usage_metadata->>'audio_duration_seconds')::float),0) audio_seconds,
       MAX(g.created_at) last_at,
       MAX(r.resolved_role_code) role, MAX(r.scene_name) scene
FROM gateway_call_records g
LEFT JOIN recordings r ON r.id = g.recording_id
WHERE g.recording_id IS NOT NULL AND g.success
  AND g.created_at >= $1 AND g.created_at < $2 {筛选: 场景/租户}
GROUP BY g.recording_id
ORDER BY {sortKey: cost DESC | last_at DESC} 
LIMIT $limit OFFSET $offset;
-- 另需 COUNT(DISTINCT recording_id) 求总数用于分页
```
- 支持按 recording_id 精确搜索（`AND g.recording_id = $x`）。
- **vs 场景均值**：需同时返回各角色均值基准。均值可用一条独立聚合查询按 role 分组算 `SUM(cost)/COUNT(DISTINCT recording_id)`，或用固定基准（医生¥0.32/咨询师¥0.44/前台¥3.03，见总体方案 2.1）。**推荐动态算**当前筛选范围内各角色均值，返回给前端做对比着色。
- 内容版：JOIN 内容表取标题/类型，business_domain='content'，按 content_id 分组。

**(f) AnomalyList — 后端真异常（替代前端 buildAnomalies）**
三类合并返回：
```sql
-- ① 单次高成本：单条调用成本 > 该 billing_subject 均值的 N 倍
-- ② 失败烧钱：按 recording_id/tenant 聚合 failed_calls 多的
-- ③ 对象高成本：TopObjects 里 failed_calls>0 或 cost 超阈值
```
实现可先做①②：
```sql
-- ① 单次高成本 Top
SELECT request_id, recording_id, content_id, tenant_id, billing_subject,
       model_code, total_cost, created_at
FROM gateway_call_records
WHERE success AND total_cost > 0 AND created_at >= $1 AND created_at < $2 {筛选}
ORDER BY total_cost DESC LIMIT 20;
-- ② 失败调用聚合
SELECT COALESCE(recording_id, content_id) AS obj_id, tenant_id,
       COUNT(*) fail_count, MAX(error_message) sample_err
FROM gateway_call_records
WHERE NOT success AND created_at >= $1 AND created_at < $2 {筛选}
GROUP BY obj_id, tenant_id HAVING COUNT(*) >= 2
ORDER BY fail_count DESC LIMIT 20;
```

**(g) RecordsPage — 分页明细（排障）**
直接分页查 gateway_call_records，支持搜 request_id / trace_id / recording_id / content_id，返回单条全字段。保留现有 `AIUsageRecordItem` DTO。

**(h) 单对象详情 — 复用/改造 by-recording / by-content**
现有 `GetAIUsageByRecording`（service.go:688）改为直连 SQL：查该 recording_id 的所有调用步骤（时间线）+ 汇总。

## 5. 完成的定义（第1层验收）
1. 运营后台所有数据来自后端 SQL 聚合，无前端本地聚合、无拉全量。
2. 全程真实人民币，无估算点数，无任何客户侧暴露。
3. 每条录音/每篇内容成本可翻页查看、可搜ID、带 vs 场景均值对比。
4. 成本结构按方案A两级(通用环节+角色分析明细)展示。

6. 后端 go test 通过；前端 build 通过；接口响应 <1s。

## 6. 注意事项
1. 本层不碰生产库写、不部署 migration，纯读+前端。部署走既有流程(api: scripts/deploy.sh DEPLOY_HOST=root@8.140.246.26；前端按 operation 既有发布方式)。
2. 成本接口必须做运营角色鉴权，严禁租户角色可达(边界铁律)。
3. SQL 全部参数化，防注入。
4. 均值基准优先"当前筛选范围动态算"，避免硬编码过期(第0层实测：医生¥0.32/咨询师¥0.44/前台¥3.03 仅作 fallback 参考)。
