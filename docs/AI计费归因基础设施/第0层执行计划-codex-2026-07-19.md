## 根因总结（已用生产数据 + 代码 + git 三方核实，不要再猜）

生产库 `lingce_prod`（阿里云 RDS）实测 3621 条调用（2026-06-20~07-18），确认三条根因链：

### 根因 A：生产网关部署的是旧二进制（未部署 HEAD）
- 生产 `gateway_call_records` 只有 22 列，归因字段（business_domain/recording_id/billing_subject 等）**全部不存在**。
- 但 llm-gateway 代码 HEAD `718d2cd` 的 `internal/store/migration.go:53-69` 已有全套 `ALTER TABLE ADD COLUMN IF NOT EXISTS` 归因字段。
- 结论：**代码是对的，生产没跑最新版**。migration 在服务启动时执行（`db.Migrate()`），生产没重启到新版本 → 字段没加。

### 根因 B：ASR 成本精确为 0 —— 旧版本的 PerMinute bug
- 生产 168 条成功 fun-asr 转写 `total_cost` **精确等于 0**（不是 0.0007，是 0）。
- git `a15372a` 版本的成本公式为 `audioDurationSeconds * pricing.PerMinute`，但配置里 fun-asr 只有 `per_second`、无 `per_minute` → `PerMinute=0` → 成本恒为 0。
- HEAD `718d2cd` 的 `internal/provider/dashscope_audio.go:162-174 calculateAudioCost` 已修正为优先读 `PerSecond`。
- 结论：**同样是生产跑旧版本**。部署 HEAD 后此 bug 自动消失（但需先解决根因 C，否则时长仍错）。

### 根因 C：音频时长来源不可靠（真实代码 bug，部署也修不了）
- 生产 `usage_metadata.audio_duration_seconds` 平均 0.931 秒、最大 7.924 秒；但对应真实录音时长几百到上万秒（`recordings.duration`，单位=秒，已实测）。差 100~3000 倍。
- 代码 `dashscope_audio.go:142`：`audioDurationSeconds := float64(dsResp.Usage.Duration) / 1000.0`。
- DashScope 对 fun-asr 返回的 `usage.duration` 不是真实音频时长（值极小，除以 1000 后更小）。
- **可靠时长其实已被解析**：`dashscope_audio.go:296-309` 的 `SentenceList[].EndTime`（毫秒）、以及 `342-355` 的 transcripts sentences `EndTime`。取 `max(EndTime)/1000` 才是真实音频秒数。
- 结论：需改代码，用句子级 `max(EndTime)` 作为时长权威来源，`usage.duration` 仅作 fallback。

### 根因 D：worker 未传归因
- `lingce-worker/internal/gateway/llm.go:22-33`（AudioInferenceRequest）、`52-66`（TextInferenceRequest）**无任何 billing 字段**。
- 录音全部步骤（转写/清洗/分析）在 worker 发起，故当前所有录音调用都无结构化归因，只能靠 trace_id 解析。

### 根因 E：内容生成打点太粗
- lingce-api content 调用全归到 `caller_module=content` / `function_type=chat`，区分不出文章/小红书/视频脚本/选题。生产仅 30 条，功能未起量。

## 任务清单（按依赖顺序，每项含：改哪、怎么改、验收）

### T1【llm-gateway 代码】修复音频时长来源（根因 C）— 最高优先

**文件**：`internal/provider/dashscope_audio.go`

**改法**：
1. 在 `extractAudioResults` 返回值增加音频时长（秒），或新增一个辅助函数从 segments 计算 `maxEndTime`。
2. 修改 `CallAudio`（line 132-143）：
   - 先调 `extractAudioResults` 得到 segments。
   - 计算 `durationFromSegments = max(segment.EndTime)`（segments 的 EndTime 已是秒，见 line 301-302 已 /1000）。
   - 时长优先级：`durationFromSegments` > `float64(dsResp.Usage.Duration)/1000.0`（仅当 segments 为空时用后者兜底）。
   - 用该时长算成本。
3. 保留 `calculateAudioCost`（已正确）。

**伪代码**：
```go
text, segments, speakerCount, err := p.extractAudioResults(ctx, dsResp)
// ...
var audioDurationSeconds float64
for _, seg := range segments {
    if seg.EndTime > audioDurationSeconds {
        audioDurationSeconds = seg.EndTime
    }
}
if audioDurationSeconds == 0 {
    audioDurationSeconds = float64(dsResp.Usage.Duration) / 1000.0 // fallback
}
totalCost := calculateAudioCost(p.pricing, modelCode, audioDurationSeconds)
```

**验收**：
- 新增/更新单测：给定 SentenceList（含大 EndTime），`audioDurationSeconds` ≈ max(EndTime)/1000，`totalCost = 时长 × 0.00022(fun-asr) > 0`。
- `go test ./...` 通过。

### T6【生产库·不可逆】历史数据回填

**分两部分，先 dry-run（SELECT 版）给你看影响行数，再执行 UPDATE：**

**6a. 回填 recording_id 等归因**（从 trace_id 解析）
```sql
-- dry-run: 先看能匹配多少
SELECT count(*) FROM gateway_call_records
WHERE recording_id IS NULL
  AND substring(trace_id from '_([0-9]+)_[0-9]{15,}$') IS NOT NULL;
-- 执行
UPDATE gateway_call_records SET
  recording_id = substring(trace_id from '_([0-9]+)_[0-9]{15,}$')::bigint,
  business_domain = 'recording',
  billing_rule_version = 'v1'
WHERE recording_id IS NULL
  AND caller_service = 'lingce-worker'
  AND substring(trace_id from '_([0-9]+)_[0-9]{15,}$') IS NOT NULL;
```

**6b. 重算 ASR 历史成本**（关键：历史成本被记为 0）
```sql
-- dry-run: 预览重算结果
SELECT g.id, r.duration, round((r.duration*0.00022)::numeric,4) AS new_cost
FROM gateway_call_records g JOIN recordings r
  ON r.id = substring(g.trace_id from '_([0-9]+)_[0-9]{15,}$')::bigint
WHERE g.function_type='transcription' AND g.success AND g.total_cost=0
LIMIT 20;
-- 执行（按真实录音时长 × fun-asr 单价重算）
UPDATE gateway_call_records g SET total_cost = r.duration * 0.00022
FROM recordings r
WHERE r.id = substring(g.trace_id from '_([0-9]+)_[0-9]{15,}$')::bigint
  AND g.function_type='transcription' AND g.success AND g.total_cost = 0;
```
- 注意：单价按模型区分（fun-asr/qwen3-asr-flash=0.00022，paraformer-v2=0.00008）。生产目前只有 fun-asr。
- 在报表标注"ASR 成本修复时间点 = 2026-07-XX"，之前口径为 0。

**验收**：回填后 `SELECT count(*) FROM gateway_call_records WHERE recording_id IS NOT NULL` 覆盖历史 worker 调用；ASR 成功记录 `total_cost > 0`。

**风险**：批量 UPDATE 生产数据。**每条 SQL 先跑 dry-run SELECT 给你确认行数与样例，再执行 UPDATE。**
