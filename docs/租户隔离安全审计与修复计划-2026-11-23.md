## 0. 威胁模型

- **admin（平台运营）跨租户 = 设计允许**，但存在三类缺口：无审计、无脱敏、`RequireTenantID` 与 `ResolveScope` 对 tenant-bound admin 口径不一致。
- **employee / mobile 必须被锁死在 token 的租户内**。任何"按 id 取对象却不对齐对象租户"的路径都是漏洞。
- 判定标准：读 → 是否泄露他人租户数据；写 → 是否能改/删/触发他人租户数据；提权 → 是否能自赋 admin。

## 3. P2：设计风险与加固（非紧急，建议排期处理）

1. **admin 全租户无审计无脱敏**：`RequireSameTenant`/`RequireTenantID`/`Authorize` 对 admin 直接放行。→ 跨租户读 PII 接口写 `system_action_logs`；统一 tenant-bound admin 口径（`RequireTenantID` 的 admin 分支与 `ResolveScope` 对齐，`tenancy/access.go:30-41`）。
2. **合规 4 个 docx 导出**只校验 JWT（`report_export.go:370`、`letter_export.go:189`），`/compliance/debug/*` 有 3 条**完全无鉴权**（`handler.go:104-125`），依赖 `app.env` 默认值 dev（`config.go:376`）。→ 生产 fail-closed；debug 路由仅在显式 dev/test 注册。
3. **全局规则表**：`compliance_rules` 无 tenant，`rule.manage` 机构管理员可改全平台规则。→ 收归 admin 或加租户维度。
4. **encounters 状态更新缺 tenant 条件**（`his/store.go:1467,1531,1556`）→ 加固补 `AND tenant_id=$1`。
5. **deal 同租户越权**：`PUT /deal-expert/approval-rules` 无 manager 校验；`PUT /deal-expert/permissions/{self}` 可自设 `deal_admin` + `data_scope=tenant`。→ 身份判定 + 禁自改角色。
6. **products 接口 fail-open**：`tenant_id=0` 语义为"不过滤"（`product/handler.go:41`、`store.go:25`）。→ 非 admin 无租户直接 401；解析失败 400。
7. **patientops 三套租户口径**：`planTenantAndEmployee` 对非 admin 静默忽略参数。→ 统一 `RequireTenantID`，不匹配 403。
8. **wecom 代开发绑定**：`POST /wecom/delegated-app/bind` 的 `corp_id` 未校验归属（`wecomv2/delegated/handler.go:228`）。→ 加租户归属校验。

## 4. 结构性防复发（一次投入，长期收益）

1. **路由 → 守卫静态测试**：新增一个 Go 测试，扫描 `Method/Path/Handler` 注册表，凡 path 带 `{id}` 且 handler 体内不包含任何租户守卫调用（`RequireSameTenant`/`RequireTenantID`/`ResolveScope`/`assertRecordingAccess`/`authorizeRecord`/`requireTenant`/… 白名单）即失败。CI 常驻，新接口漏守卫直接红。
2. **统一 helper**：把"按 id 取对象 + `RequireSameTenant`"沉淀为 `loadOwned[T](r, id, getter)` 一类小函数；各模块已有的正例（`emrrecord/handler.go:82-95`、`customer/handler.go:291-317`、`recording/handler.go:598-606`）为范本。
3. **SQL 兜底**：跨租户敏感表的主 JOIN（`recordings`、`customers`、`encounters`、`emr_records`）全部带 `AND x.tenant_id = y.tenant_id`；`deal_outcome_events`/`sales_tasks` 补复合唯一约束 `(tenant_id, recording_id)`。
4. **审计**：跨租户读 PII 的 ops 接口（后续做产物查看时一并）写 `system_action_logs`。
