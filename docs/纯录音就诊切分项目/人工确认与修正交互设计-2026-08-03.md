# 人工确认与修正交互设计

日期:2026-08-03
状态:已确认,纳入 demo 开发

## 本文目的

定义医生/助手在切分结果页面上能做什么操作、怎么做、做完之后数据怎么用。

## 一、设计原则

### 核心交互原语:指着对话里的某一行说"这里"

对话按轮次带时间戳显示,每一行天然就是一个可选的切点。所有修正操作都可以归结为指定某一行的位置 + 声明一个动作。

### 验证流程要快

目标:8 次就诊,2 分钟验完。90% 的情况是确认正确(1 秒一张),只有 10% 需要展开对话修改。

### 修正结果即评估集

医生改完的结果就是这条录音的正确答案。存下来后,后续改 prompt 可自动跑比对,不再需要人介入。一次修正,无限复用。

## 二、六种操作

### 操作 1:确认正确

场景:这次就诊切得对,患者、边界都对。

操作:点 `✓ 正确` 或按 `Y`

效果:
- 卡片标绿,右上角绿色勾
- 自动跳到下一张卡片
- 顶部进度更新

占比:约 90%。这个操作必须极快,一个键完成。

### 操作 2:与上一段合并

场景:同一个患者被切成了两张卡(多切)。

操作:点 `↑ 与上一段合并` 或按 `M`

效果:
- 当前卡片和上一张合并成一张
- 合并后卡片的时间范围扩展为两者之和
- 摘要重新生成(合并后文本变了)
- 后续卡片重新编号
- 合并动作记录到修正日志

示例:就诊 #3 和就诊 #4 其实是同一个患者,在 #4 上点合并,结果变成新的就诊 #3(时间拉通),原来的 #5 变成新的 #4。

### 操作 3:在此处切开

场景:一张卡里其实有两个患者(漏切)。这是最严重的错误。

操作:
1. 展开完整对话
2. 鼠标划过对话行时,行首出现剪刀图标 ✂
3. 点击某一行 → 这张卡从该行裂成两张,该行成为新就诊的第一句

视觉示意:
```
[14:20] 医生:好,回去按时吃药
[14:28] 患者:谢谢医生
───────────────────────────────
✂ [14:35] 医生:下一个,坐吧      ← 点这里切开
[14:44] 患者:我这个咳嗽两周了
[15:01] 医生:咳了多久?
```

效果:
- 当前卡片裂成两张,新卡片从点击行开始
- 两张卡各自重新编号
- 摘要各自重新生成
- 切开动作记录到修正日志

### 操作 4:调整边界位置

场景:切分位置差了几句。比如把上一个患者的告别话算进了这次就诊。

操作:
1. 展开完整对话
2. 鼠标划过对话行时,行首出现选项
3. 点击行首 → 出现两个选择:`⬆ 这里才是开始` / `⬇ 这里才是结束`

点 `⬆ 这里才是开始`:
- 该行之前的内容退出当前卡片,归给上一段(如果是 encounter)或归为间隙
- 当前卡片的起始时间更新为该行的时间

点 `⬇ 这里才是结束`:
- 该行之后的内容退出当前卡片,归给下一段或归为间隙
- 当前卡片的结束时间更新为该行的时间

### 操作 5:这不是一次就诊

场景:模型把非就诊内容(如医生和护士聊天)误判为 encounter。

操作:点 `✗ 不是就诊` 或按 `D`

效果:
- 该卡片从就诊视图中消失
- 对应时间段降级为 non_encounter_talk
- 后续卡片重新编号

### 操作 6:补充一次遗漏的就诊

场景:模型把一次真实就诊误判为非就诊内容(idle/non_encounter_talk),导致它不出现在就诊视图里。

触发:验证完所有卡片后,页面显示提示:

```
另有 15 段被判定为非就诊内容
其中 5 段时长超过 1 分钟,建议检查是否有遗漏 →
```

点进去后:
- 只显示时长超过 1 分钟的非就诊段(短于 1 分钟基本不可能是就诊)
- 每段显示开头 5 轮对话
- 如果某段其实是就诊,点 `+ 这是一次就诊`

效果:
- 该段升级为 encounter,插入就诊视图的正确时间位置
- 重新编号
- 生成摘要

## 三、键盘快捷键

| 按键 | 动作 |
|---|---|
| `Y` 或 `→` | 确认正确,跳下一张 |
| `N` | 展开对话查看(不标记) |
| `M` | 与上一段合并 |
| `D` | 标记不是就诊 |
| `空格` | 展开/收起完整对话 |
| `↑` / `↓` | 移动焦点,不做任何标记 |

操作 3(切开)和操作 4(调边界)需要指定具体行,必须用鼠标,不设快捷键。

当前焦点卡片必须有明显视觉标识(左侧蓝色竖线或整卡加粗描边)。

页面某处常驻显示快捷键说明。

## 四、验证完成后的汇总

全部卡片验证完毕,页面显示:

```
验证完成

AI 切出:8 次就诊
人工确认:9 次就诊

操作统计:
  确认正确:6 次
  与上一段合并:1 处 (多切修正)
  切开:1 处 (漏切修正)
  调整边界:1 处
  标记不是就诊:0 处
  补充遗漏:1 次

指标:
  漏切:1 处 (严重)
  多切:1 处 (轻微)
  边界偏移:1 处 (轻微)
  准确率:6/9 = 67%
```

这就是本次 prompt 效果的完整评价。换一版 prompt 重新跑,直接比这几个数。

## 五、保存修正结果(关键)

### 为什么必须保存

如果修正结果不保存,医生的每次修正都是一次性的,下次改 prompt 还得人重新过一遍。这是巨大的浪费。

保存下来后:
- 它是这条录音的 ground truth,后续自动评测用
- 攒够 15-20 条,迭代 prompt 完全不需要人参与
- 标注成本从"每轮都投入"变成"一次投入,无限复用"

### 保存什么

修正完成后,点 `保存为基准` 按钮,存成一个 JSON 文件:

```json
{
  "recording_id": 12345,
  "duration_seconds": 2292,
  "annotated_at": "2026-08-03T14:30:00Z",
  "annotated_by": "dr_wang",
  "encounters": [
    {
      "seq": 1,
      "start_seconds": 0,
      "end_seconds": 412,
      "patient_hint": "阿姨,胃疼",
      "source": "ai_confirmed"
    },
    {
      "seq": 2,
      "start_seconds": 450,
      "end_seconds": 890,
      "patient_hint": "小伙子,咳嗽",
      "source": "ai_confirmed"
    },
    {
      "seq": 3,
      "start_seconds": 890,
      "end_seconds": 1320,
      "patient_hint": "大爷,腰痛",
      "source": "human_split"
    }
  ],
  "corrections": [
    {"type": "split", "original_encounter_seq": 2, "split_at_seconds": 890},
    {"type": "merge", "merged_seqs": [4, 5]},
    {"type": "add", "from_segment_index": 15}
  ]
}
```

`source` 字段说明这个 encounter 是 AI 切的人工确认了(`ai_confirmed`),还是人工切开产生的(`human_split`),还是人工补充的(`human_added`)。

`corrections` 数组记录了所有修正操作,便于分析"模型到底在什么地方犯错"。

### 保存到哪里

MVP 阶段不写数据库。两种选择:
- 方案 A:存到本地文件 `data/annotations/recording_12345.json`
- 方案 B:存到开发数据库的一张简单表 `encounter_annotations`

建议先用方案 A,简单直接。后面上线时再迁到数据库。

## 六、自动评测(第二阶段)

攒够 3 条以上基准文件后,写一个评测脚本:

输入:prompt 版本 + 基准文件列表
流程:对每条录音跑切分 → 将 AI 结果与基准比对
输出:

```
评测报告 (prompt v0.3, 2026-08-05)

录音 12345 (38分):AI 8次 vs 基准 9次,漏切1,多切0,偏移1
录音 23456 (72分):AI 15次 vs 基准 14次,漏切0,多切1,偏移2
录音 34567 (240分):AI 31次 vs 基准 30次,漏切0,多切1,偏移0

汇总:
  平均漏切:0.33 次/录音
  平均多切:0.67 次/录音
  平均偏移:1.0 处/录音
  encounter 匹配率:89%
```

比对逻辑:
- AI 的 encounter 和基准的 encounter 按时间重叠度配对(重叠 > 50% 视为同一个)
- 基准中有但 AI 没匹配上的 → 漏切
- AI 中有但基准没匹配上的 → 多切
- 匹配上了但起止时间差超过 30 秒 → 边界偏移

这个脚本是第二阶段做,不阻塞 MVP 发布。

## 七、发布判断

什么时候可以上线:

- 前端交互好用(医生 2 分钟验完 8 次就诊)✓ 由本文档保证
- 漏切率低(平均每条录音 < 0.5 次)← 用评估集量化
- 医生平均修正次数低(< 1 处/录音)← "AI 帮我省事"而不是"AI 给我添活"

第一条现在就能验证。后两条需要攒几条基准之后看数据。

但不需要专门组织标注。**医生在验证页面上修正 → 保存为基准 → 自然攒够 → 数据自己告诉你能不能上线。**

## 附:与任务书其他部分的关系

- 就诊摘要卡(患者/主诉/处置/开场/结束)不变,它是"3 秒判断"的基础
- 边界检查区不变,它是操作 3/4 的辅助工具
- 完整时间轴视图不变,它是操作 6 的入口
- 本文档新增的是六种操作的定义、键盘快捷键、保存和评测逻辑
