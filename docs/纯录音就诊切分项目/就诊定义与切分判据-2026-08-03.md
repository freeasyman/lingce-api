# 就诊定义与切分判据

日期:2026-08-03
状态:已确认,可作为 MVP 开发依据

## 本文目的

在写任何代码之前,先把两件事定下来:

1. 什么算一次就诊(定义和边界裁定)
2. 切分层应该产出什么(数据模式)
3. 靠什么信号识别边界(判据和优先级)

本文不涉及表结构、接口、前端。那些等切分能力验证通过之后再定。

## 一、什么是一次就诊

### 核心判据

一次 `encounter` 是**一个患者与一个医生之间的一段连续诊疗交互**。三个要素必须同时成立:

- 单一患者(含其家属陪同)
- 有诊疗意图(问诊、查体、解释、开方、医嘱,至少其一)
- 时间上连续(允许内部有短暂中断)

### 边界裁定

以下 case 需要明确裁定,避免标注和 prompt 各自理解:

| 场景 | 裁定 | 说明 |
|---|---|---|
| 同一患者连续讲两个不相关问题 | 一次 | 患者未离开 |
| 家属代述,患者本人不在 | 一次 | 患者身份仍唯一 |
| 患者中途出去做检查,回来继续 | 一次 | 视为内部中断,不切开 |
| 医生离开一会儿,患者留在诊室 | 一次 | 同上 |
| 医生和护士/同事讨论排班、器械 | 不是就诊 | 归为非就诊对话 |
| 医生和同事讨论某位患者病情 | 不是就诊 | 归为非就诊对话,但需保留,含临床信息 |
| 医生接私人电话 | 不是就诊 | 归为非就诊内容 |
| 患者只是进来问路、拿报告,无诊疗 | 不是就诊 | 无诊疗意图 |
| 两位患者同时在诊室(如夫妻同诊) | 一次,标 multi_patient | 不硬切,边界会交织;身份归属是第3层的问题 |

### 一次就诊的内部允许中断

不因下列情况切开:

- 短静默(经验值 30 秒以内,需用真实数据校准)
- 医生查阅资料、书写记录的静默
- 患者离开做检查后返回

## 二、切分层产出什么

### 原则:对整条录音的时间轴做完整覆盖

切分层的输出不是"encounter 列表",而是**整条录音的分段列表,每段都有类型**。类型至少包括:

- `encounter` — 一次就诊
- `non_encounter_talk` — 非就诊对话(同事交流、电话)
- `idle` — 静默或无有效内容
- `uncertain` — 无法判定类型,需人工复核

完整覆盖的好处:时长可校验,不会出现"中间 8 分钟去哪了"这种说不清的情况。调试和人工复核时价值很大。

### 每段携带的信息

| 字段 | 含义 |
|---|---|
| 序号 | 在录音内的顺序 |
| 类型 | 见上表 |
| 起止时间 | 相对录音开始的偏移 |
| 段内文本 | 该段的转写内容 |
| 置信度 | 该段边界判定的可信程度 |
| 命中信号 | 判定依据了哪些信号,见第三节 |

### 切分层不做的事

明确排除,避免职责混淆:

- **不做患者身份识别**。不提取姓名、年龄、性别,不与客户主档匹配。
- **不做内容分析**。不生成主诉、诊断、病历、评分。
- **不做素材提取**。

理由:身份识别经常失败(患者未自报姓名、家属代述、方言口音)。如果切分依赖身份,一次识别失败会连带毁掉边界判定。而边界本身靠静默、说话人切换、结束语就能定,不需要知道患者是谁。

身份和内容都属于下一层的职责。

## 三、如何识别边界

### 信号分级

按可靠性排序,高等级信号应有更高权重:

**强信号**
- 叫号或点名:"下一个"、"张三"、"李阿姨来了"
- 明确的结束语:"没什么问题了"、"回去吃药"、"下周再来"
- 明确的开场语:"哪里不舒服"、"什么时候开始的"
- 长静默(阈值待用真实数据校准)

**中等信号**
- 主诉突变且前后无关联
- 说话人音色变化(依赖 speaker diarization,当前不一定可用)
- 称谓变化:"阿姨"变成"小伙子"
- 寒暄模式重现:"坐吧"、"来,坐这儿"

**弱信号**
- 语速语调回到问诊开场状态
- 固定问诊句式重复出现

### 核心原则:切错的代价不对称

这是切分调优最重要的约束,不能用单一准确率指标掩盖。

**切多了**(一次就诊被切成两段):一个患者产出两份不完整病历。难看,但可恢复,人工合并即可。

**切少了**(两个患者被合成一段):A 患者的主诉和 B 患者的诊断混进同一份病历。这是**临床安全问题,也是数据泄露问题**,而且很难发现——生成的病历读起来通顺,只是内容错了。

**因此:边界判定主动偏向多切。** 宁可产出碎片让人工合并,也不要漏切。

具体含义:
- 拿不准的地方,倾向切开
- 后处理里"合并相邻碎片"的逻辑要格外保守,它是把两个患者粘起来的主要风险来源
- 评估指标要把漏切和多切分开统计,不能只看总体准确率

### 置信度的用途

置信度不只是展示用,它应该是**闸门**。

低置信度的段落,不应该直接进入下游分析。理由:置信度 0.6 的边界直接生成病历,等于把已知有问题的输入喂给下游,再给出一份看起来正规的输出。

阈值和阻断策略待定,见第五节。

## 四、分层约定

三层各自职责固定,不互相渗透:

```
第1层  录音 → 转写            事实层,不含判断
第2层  转写 → 分段(含 encounter)  只回答"边界在哪"
第3层  encounter → N 种分析     病历、沟通分析、素材…
```

分层的理由是每层稳定性不同:

- 第1层几乎不变,换 ASR 供应商才动
- 第2层逻辑会反复调优,但产出格式极稳定(就是时间区间加类型)
- 第3层会持续增加新类型

第2层的产出是可复用的中间资产:一次切分,N 种分析各跑各的,互不影响,失败可单独重试。

## 五、已确认的决定

经讨论确认,以下 6 条作为 MVP 阶段的约束:

### 5.1 夫妻/母子同诊

不硬切。标记为一个 encounter,附 `multi_patient: true`。

理由:医生交替问两个患者时时间轴交织,硬切会制造大量断裂。如果下游需要出两份病历,那是第3层的问题。第2层不承担身份归属。

### 5.2 长静默阈值

不预先定死。MVP 阶段让模型输出 `silence_gap_seconds` 和 `boundary_reasons`,我们统计 10 条后再定。

临时参考区间(必须结合上下文,不单独使用):
- < 30s:不作为强信号
- 30-90s:中等信号
- > 90s:强信号

### 5.3 低置信度阻断策略

先软阻断:`needs_review: true`,照样生成分段,但标记待复核。不硬阻断。

理由:MVP 阶段需要看到坏结果才能调 prompt。硬阻断会影响验证效率。

### 5.4 非就诊文本处理

保留文本,但不进入下游病历分析。

- `segment_type: non_encounter_talk`
- 附 `contains_clinical_info: true/false`(区分是否含临床讨论)
- 仅 ops 可见,不暴露给终端用户

### 5.5 评估集

必须建,且先只建小集。从 10 条里选 3 条精标:

- 1 条短(encounter 数少,边界清晰)
- 1 条中等
- 1 条超长(如 1797 秒级)

只标边界,不标病历内容。评估指标:
- 漏切(两个患者粘在一起)—— 严重
- 误切(一个患者被切成两段)—— 轻微
- 边界偏移秒数
- 非就诊段识别准确率

### 5.6 调用策略

MVP 先全文或分块全文,不做复杂候选点逻辑。

但超长录音(240 分钟)会超模型上下文窗口。实际工程做法:按 ASR 时间片分块 → 模型输出局部分段 → 二次合并边界。不是一次把全文塞进去。

分块粒度和合并策略在跑通基本链路后再调。

## 六、MVP 切分输出契约

### 底层对象:segment

切分层的原子产出是 `segment`,不是 encounter。encounter 只是 `segment_type = "encounter"` 的那些段。

### 字段定义

```
segment {
  index:                int       // 在录音内的顺序,从 1 开始
  segment_type:         string    // encounter | non_encounter_talk | idle | uncertain
  start_seconds:        int       // 相对录音起始的偏移(秒)
  end_seconds:          int       // 相对录音起始的偏移(秒)
  boundary_confidence:  float     // 0.0 ~ 1.0,该段边界判定的可信度
  boundary_reasons:     []string  // 判定依据的信号,如 ["closing_phrase", "silence_45s", "next_patient_call"]
  silence_gap_seconds:  int?      // 该段与下一段之间的静默时长(便于后续统计阈值)
  needs_review:         bool      // 置信度低或类型不确定时为 true
  multi_patient:        bool      // 仅 encounter 类型有效,疑似多位患者同时就诊
  contains_clinical_info: bool?   // 仅 non_encounter_talk 类型有效,是否含临床信息
  text_preview:         string    // 该段前 200 字摘要(用于列表展示,不是完整转写)
}
```

### 约束

- 所有 segment 连续不重叠,且完整覆盖录音时间轴:`seg[0].start_seconds = 0`,`seg[n-1].end_seconds = 录音总时长`
- `seg[i].end_seconds = seg[i+1].start_seconds`(无间隙无重叠)
- 如果某段静默独立存在,归为 `idle`;如果静默嵌在 encounter 内部(< 阈值),不切出来

### 完整转写文本怎么给

两种方式(MVP 先选一种):
- A: segment 里带 `full_text` 字段,直接包含完整转写(简单,但 JSON 很大)
- B: segment 只给 `text_preview` + `start_seconds/end_seconds`,完整文本按时间区间从已有转写里裁取(轻量,但需要转写有时间戳)

建议 MVP 用 A。不要过早优化传输大小。

### 提示词的核心任务语言

给模型的指令应该是:

> 请把整条录音转写文本的时间轴切成连续、不重叠、完整覆盖的片段。每个片段只判断类型和边界。不要识别患者身份,不要生成病历分析。遇到疑似不同患者时,优先切开;遇到不确定边界时标记低置信度和待复核。

不要问"切出就诊列表",那会暗示模型只输出 encounter 而忽略非就诊段。



这些是架构和产品层面的结论,记录备查,不在切分验证阶段处理:

- **业务标的物要从"录音"转为"就诊"**。录音库退化为底层素材,前端主入口应是医生的就诊、咨询师的咨询、康复师的治疗。整个体系需要重新组织。
- **`recordings.customer_id` 是单值,与"一条录音 N 个患者"冲突**。长录音的患者归属只能存在于 encounter 层。
- **encounter 在系统里的身份未定**:是 recordings 表里的一行(带 parent_recording_id),还是独立实体。前者复用现有下游代码成本低,后者更干净但改造量大。
- **切分应作为分析 pipeline 的一步**,复用现有 `analysis_runs` / `analysis_steps` 的审计和成本归因体系,而不是另起一套。
- **重切之后旧 encounter 和其分析结果如何处置**。倾向版本式:一次切分是一个 run,结果不可变,人工修正作用在特定版本上。
- **第3层的粒度不总是 encounter**。素材可能是 encounter 内的子片段,也可能跨 encounter 挑选。不能按 1:1 设计。
- **素材对外发布需要独立授权**。病历和沟通分析是内部使用,素材是对外,性质不同,需要可追溯的患者授权,且默认拒绝。
