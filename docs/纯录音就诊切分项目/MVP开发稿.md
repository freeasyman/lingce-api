# 纯录音就诊切分项目 MVP 开发稿

## 目标

从现有医生录音列表发起单条重新切分，经过既有分析链路生成 `encounter`，在就诊列表查看结果，在就诊详情查看基本信息。

## 关键约束

- 前端不能直接调用大模型。
- 所有分析必须走现有录音分析链路和运行审计体系。
- 迭代重点放在提示词和小范围代码修改，不频繁改大架构。

## 现有链路

1. 医生录音列表选择一条长录音。
2. 点击“重新切分”。
3. 后端走录音动作接口，进入分析任务队列。
4. 分析结果进入运行审计。
5. 切分后的 `encounter` 落库或生成可查询结果。
6. 就诊列表展示结果。
7. 就诊详情展示基础信息。

## 最小页面

- `医生录音列表`
- `就诊列表`
- `就诊详情`
- `运行审计`（可复用现有页面）

## 最小交互

- 录音行内按钮：`重新切分`
- 结果刷新：按运行状态自动轮询
- 结果入口：完成后可跳到就诊列表或运行审计

## 数据对象

- `录音`：分析入口与原始素材。
- `分析运行`：一次切分任务的执行记录。
- `就诊 encounter`：切分后的业务结果。

## MVP 验收

- 能对单条长录音发起切分。
- 能看到分析运行过程和结果。
- 能在就诊列表看到生成的 encounter。
- 能点进就诊详情看到基本信息。

## 后续迭代

- 先改提示词。
- 再改少量切分规则。
- 最后才考虑更完整的产品组织。
