日期：2026-08-07
交付对象：Codex
前置文档：`docs/纯录音就诊切分项目/前端线框图-2026-08-03.md`（线框图）

## 目标

现在的 demo 页面把三件不相关的工作挤在一屏里，没人看得懂该先点哪里。重构成三个独立页面，每个页面只做一件事。同时把深色背景换成浅色。

**不改后端逻辑和 API。** 所有现有接口保持不变，只重写前端 HTML/CSS/JS。

---

## 硬性要求

### 配色

删掉现有的深色主题，换成浅色：

```css
:root {
  --bg: #f5f6f8;
  --card: #ffffff;
  --border: #e2e5e9;
  --text: #1a1a1a;
  --muted: #6b7280;
  --green: #16a34a;
  --blue: #3b82f6;
  --gray: #9ca3af;
  --amber: #d97706;
  --red: #dc2626;
  --btn-primary: #2563eb;
  --btn-secondary: #f3f4f6;
}
```

语义色用途：绿=就诊、蓝=非就诊、灰=静默、琥珀=待复核/已修正、红=漏切/严重错误。

### 文件结构

仍然是单 HTML 文件 `internal/splitdemo/static/index.html`，用 Go embed 嵌入。三个页面用前端路由切换（hash route: `#annotate` / `#test` / `#build`），不刷新页面。

### 顶部导航

三个 tab：「标注录音」「跑测试」「造用例」。当前激活的加下划线。默认落地页是「标注录音」。

## 页面一：标注录音（#annotate）

给运营用的。核心交互：选一条录音 → 看切分结果 → 逐条确认就诊卡片。

### 布局

左右两栏：
- 左栏（窄，约 280px）：筛选条件 + 录音列表 + 归因统计
- 右栏（宽，剩余空间）：时间轴 + 就诊卡片列表

### 左栏

**筛选条件（默认折叠）：**
- 租户 ID（input，默认 1）
- 最小时长秒数（input，默认 600）
- 「筛选」按钮

点筛选后刷新录音列表。折叠状态下只显示「筛选 ▾」一行。

**录音列表：**
- 每行显示：员工名、日期、时长
- 已标注的显示 ✓ 标记
- 选中高亮
- 调用 `GET /internal/split-demo/recordings`

**归因统计（有数据时才显示）：**
- 本条录音的修正分布（如：合并 2、删除 1）
- 全局汇总（如：患者返回 32%、同事交流 24%）
- 调用 `GET /internal/split-demo/annotation-overview`（如果有这个接口）或在前端计算

### 右栏

**选中录音后：**

1. 自动调用 `GET /internal/split-demo/recordings/{id}` 获取详情
2. 自动调用 `POST /internal/split-demo/split` 执行切分（用当前默认 prompt）
3. 切分进行中显示进度条和状态文字
4. 切分完成后显示：

**时间轴条：** 和现有一样的彩色横条，但放在顶部，占一行。

**就诊卡片列表：** 只展示 `segment_type === 'encounter'` 的片段。每张卡片包含：

```
就诊 #N                              HH:MM - HH:MM
┌──────────────────────────────────────────────────┐
│  患者: xxx                                        │
│  主诉: xxx                                        │
│  处置: xxx                                        │
│                                                    │
│  [✓ 正确]  [合并↑]  [不是就诊]                    │
│                                                    │
│  ▶ 展开对话                                       │
└──────────────────────────────────────────────────┘
```

- 确认后卡片左边框变绿
- 合并/删除后卡片左边框变琥珀
- 当前焦点卡片左边框变蓝、加阴影

**快捷键：** Y/→ 确认、M 合并、D 删除、↑↓ 切换焦点、空格展开/收起

**原因弹窗：** merge/delete 时弹出原因选择，和现有逻辑一致。必填。

**进度和保存：**
- 卡片列表上方显示「已确认 5/12」
- 全部确认后显示「保存标注」按钮
- 调用 `POST /internal/split-demo/save-annotation`

### 这个页面不出现的东西

- ❌ System Prompt / User Prompt 编辑框
- ❌ 模型选择
- ❌ 提示词版本输入
- ❌ 合成测试相关的任何控件
- ❌ 原始 JSON 输出（收到页面底部折叠 details 里）

只在页面右上角用小字标注「当前 prompt: v0.2」（从最近一次运行的 prompt_version 取）。

## 页面二：跑测试（#test）

改 prompt 后看效果用的。核心循环：编辑 prompt → 选用例 → 运行 → 看结果对比。

### 布局

上下两区：
- 上区：提示词编辑
- 下区：左右分栏（左=用例列表，右=结果展示）

### 上区：提示词编辑

一行元信息：版本号（input）、模型（input，默认 qwen-max）

两个并排 textarea：System Prompt（左）、User Prompt（右）。预填现有默认值。

### 下区左栏：用例列表

显示所有合成用例，每个用例一行：
- 名称
- 上次运行的召回率（如 `召回 83%`）
- 如果没跑过显示「未测试」

底部两个按钮：
- 「▶ 运行选中用例」
- 「全部运行」（批量跑所有用例，汇总结果）

调用 `GET /internal/split-demo/synthetic/cases`

### 下区右栏：结果展示

**这是整个重构最重要的部分。** 不能再用 JSON.stringify dump 了。

运行完成后（调用 `POST /internal/split-demo/synthetic/run`，轮询 `GET /internal/split-demo/synthetic/runs/{id}`），按以下结构渲染 `EvalReport`：

**头部摘要：**

```
用例名称                           prompt 版本

┌─────────┐  ┌─────────┐
│ 漏切 N  │  │ 过切 N  │
│ (严重)  │  │         │
└─────────┘  └─────────┘

召回 XX% (N/M)    精确 XX% (N/M)
平均偏移 Ns        最大偏移 Ns
```

漏切的框用红色边框，过切用琥珀色。如果漏切为 0 则变绿色框显示「漏切 0 ✓」。

**按信号类型分组（by_gap_type）：**

```
哪种边界最弱

  静默            3/3  ✓✓✓
  叫号            2/2  ✓✓
  无提示直接切换   0/1  ✗  ← 弱点
```

全对的显示绿色 ✓，有漏切的显示红色 ✗ 并标注「← 弱点」。这个区块非常重要，它直接告诉用户 prompt 该往哪改。

**边界明细（details）：**

按优先级排序：漏切 > 过切 > 命中。

漏切（红色背景条）：
```
✗ 漏切  应在 MM:SS   信号类型
  上文  …最后 80 字
  下文  最前 80 字…
```

过切（琥珀色背景条）：
```
✗ 过切  AI 切在 MM:SS
  上文  …最后 80 字
  下文  最前 80 字…
```

命中（默认折叠，点击展开）：
```
✓ 命中  应在 MM:SS → AI MM:SS (偏 Ns)  信号类型
```

`context_text` 字段拆成上文/下文显示。如果 API 返回的是完整一段，按边界位置的文本前后各取 80 字。

**「和上次比」区块：**

如果同一用例有上一次运行记录（从 `SyntheticCaseDetail.previous_runs` 取），自动渲染对比：

```
v0.1 → v0.2:
  + 边界#3 从漏切变命中 (改善)
  - 边界#5 从命中变过切 (退化)
  = 其余 4 个不变
```

改善用绿色，退化用红色。如果没有历史运行则不显示此区块。

### 运行中状态

和现有逻辑一致：显示进度条、分块进度、耗时。但状态区放在结果展示的顶部而不是用例列表里。

## 页面三：造用例（#build）

从上到下三步线性流程。

### 第 1 步：选素材

标题：「选素材 — 候选短录音（3-15 分钟）」

调用 `GET /internal/split-demo/synthetic/candidates` 获取候选列表。

每条录音一行：
- 勾选框
- ID、员工名、时长
- 转写文本前 50 字预览
- 「展开全文」按钮（展开后显示完整转写文本，用于确认是单患者）

底部显示：「已选 N 条，预计拼接时长约 X 分钟」

### 第 2 步：配置接缝

标题：「配置接缝 — 每个连接处设置信号类型」

已选的录音按顺序纵向排列，每两条之间插入一个「接缝配置」区块：

```
┌ #1 录音 ID xxxx 员工名 时长 ─────────────────┐
│  首句…                                尾句… │
└──────────────────────────────────────────────┘
        ↕
┌─ 接缝 A ────────────────────────────────────┐
│  间隔 [  60  ] 秒                            │
│  信号类型 [静默（无任何对话）          ▾]     │
└──────────────────────────────────────────────┘
        ↕
┌ #2 录音 ID xxxx 员工名 时长 ─────────────────┐
│  首句…                                尾句… │
└──────────────────────────────────────────────┘
```

信号类型下拉选项（直接写中文，不要显示英文枚举值）：
- 静默（无任何对话）—— 只留时间间隔
- 叫号（插入"下一个"）—— 间隔内插入一句
- 结束语（插入"好就这样，回去吃药"）—— 间隔内插入一句
- 无提示直接切换 —— 自动把间隔设为 0 秒，灰掉间隔输入框
- 同事插话（插入医生与护士的对话）—— 间隔内插入几句

每条录音显示首尾各一句话（方便确认就诊的开头和结尾），并允许拖拽调整顺序。

### 第 3 步：预览和保存

标题：「预览和保存」

两个输入框：
- 用例名称（如「静默+无提示-3患者」）
- 说明（如「测试静默 60 秒和无提示直接切换两种边界」）

「预览拼接结果」按钮 → 调用 `POST /internal/split-demo/synthetic/preview`

预览区显示：
- 总时长
- 正确边界列表（秒数 + 信号类型）
- 拼接后文本前 500 字

「保存用例」按钮 → 调用 `POST /internal/split-demo/synthetic/cases`

保存成功后提示「已保存，可到"跑测试"页面运行」，并提供跳转链接。
