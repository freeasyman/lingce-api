# 前端修补 — Codex 指令

日期：2026-08-07
文件：`internal/splitdemo/static/index.html`

## 修三个问题

### 1. 取消自动切分

现在打开「标注录音」页面，加载录音列表后会自动选中第一条并立即调 LLM 切分，白烧 token。

改成：
- 加载列表后不自动选中任何录音
- 用户必须手动点选一条录音
- 点选后先加载录音详情（转写文本），但**不自动切分**
- 显示一个「执行切分」按钮，用户点了才调 LLM
- 如果该录音已有 `latest_run`（之前跑过），直接展示历史结果，不重跑

### 2. Tab 顺序调整

现在：标注录音 / 跑测试 / 造用例

改成：**造用例 / 跑测试 / 标注录音**

原因：实际使用顺序是先造用例、再跑测试、最后才做真实录音标注。从左到右符合操作流程。

默认落地页改为 `#build`（造用例），因为新用户第一件事是造一个用例。

### 3. 空状态提示

「跑测试」页面的用例列表为空时，不要只显示空白。显示引导文案：

```
还没有测试用例

测试用例 = 几条短录音拼接成的假长录音。
你知道正确的切分位置在哪，所以能自动算出 AI 的准确率。

[去造第一个用例 →]
```

点击链接跳转到 `#build`。

同理，「造用例」页面的候选录音列表为空时（API 返回空数组），显示：

```
没有找到候选录音

请确认开发数据库里有 tenant_id=1、时长 3-15 分钟、已完成转写的医生录音。
```

## 顺带改的小事

- Tab 文字改名：
  - 「标注录音」→「真实录音标注」
  - 「跑测试」→「合成测试」
  - 「造用例」→「造测试用例」
- Hash route 对应改为：`#build` / `#test` / `#annotate`（顺序变了但 hash 值不变，不影响外部链接）

## 不改的

- 后端代码不动
- 配色、布局、三页面结构不动
- 快捷键、原因弹窗等交互不动
