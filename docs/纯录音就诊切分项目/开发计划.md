# 纯录音就诊切分项目开发计划

## 原则

- 先跑通闭环，再补完整组织。
- 先做最小前端，再做大改版。
- 先高频迭代算法和提示词，再追求结构完整。

## MVP 范围

- 录音上传与列表。
- 自动切分 `encounter`。
- 详情页展示切分结果、转写、置信度。
- 支持合并、拆分、确认、驳回。
- 支持低置信反馈回流。

## 非目标

- 不做完整菜单重构。
- 不做全新的业务中台。
- 不做一次性“全自动完美切分”。

## 阶段划分

### 第 1 阶段：最小闭环

- 接入现有录音数据。
- 输出 encounter 切分结果。
- 前端仅增加结果页和修正动作。

### 第 2 阶段：可迭代版本

- 增加人工修正反馈。
- 增加低置信样本池。
- 基于真实样本迭代规则、模型和提示词。

### 第 3 阶段：产品化

- 再决定是否把 `就诊` 升级为主对象。
- 再梳理菜单、首页和工作台结构。

## 开发节奏

- 算法与提示词：高频迭代。
- 前端：只做支撑 MVP 的最小页面。
- 组织结构：延后处理。

## 验收标准

- 能稳定产出 encounter 切分结果。
- 人工可快速修正。
- 修正结果能回流。
- 可以连续跑真实录音样本。

## 关键风险

- 纯录音场景边界天然不完美。
- 没有反馈闭环，算法会停在静态规则。
- 过早重构前端会拖慢上线。

## 结论

先把“录音 -> encounter -> 修正 -> 回流”做成最小可用闭环，其余结构后置。
