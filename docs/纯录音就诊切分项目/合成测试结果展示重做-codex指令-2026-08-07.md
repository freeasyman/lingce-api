# 合成测试结果展示重做 — Codex 指令

日期：2026-08-07
文件：`internal/splitdemo/static/index.html` + 后端少量改动

## 问题

现在合成测试跑完显示的是「漏切 1 处 / 召回 0% / 按信号类型分组」这类统计指标，人看不懂，也看不出 AI 到底切成了什么样。

统计指标是给机器看的。人需要看到的是：**我放进去 3 段就诊，AI 切出来几段，内容对不对。**

## 新的展示逻辑

合成用例的正确答案本质上是「应该有 N 次就诊，每次的内容是什么」，而不是「边界在第几秒」。所以结果展示要改成左右对照：

左右两列的卡片样式复用「真实录音标注」页面的就诊卡片（患者 / 主诉 / 处置三行），保持视觉一致。

### 判定标记

左列每个素材下方标注它的命中情况：

| 情况 | 标记 | 颜色 |
|---|---|---|
| 恰好对应 1 个 AI 就诊 | ✓ AI 识别出来了 | 绿 |
| 和其他素材被合并成 1 个 | ✗ AI 没识别出来，被合并进就诊 #N | 红 |
| 被切成了 2 个以上 | ⚠ AI 切成了 2 段（就诊 #2、#3） | 琥珀 |
| 完全没有对应的 AI 就诊 | ✗ AI 判定这段不是就诊 | 红 |

右列每个 AI 就诊下方标注：

| 情况 | 标记 | 颜色 |
|---|---|---|
| 对应 1 个素材 | ✓ 对应素材 #N | 绿 |
| 跨了多个素材 | ⚠ 这一段吞掉了素材 #N、#M | 红 |
| 只对应半个素材 | ⚠ 素材 #N 的一部分 | 琥珀 |

### 「看详情」展开

点开后显示该边界位置的原文，这是判断 AI 为什么错的唯一依据：

## 匹配算法（后端）

新增一个匹配步骤，把 AI 切出的 encounter 和素材的时间范围做重叠匹配。

每个素材在合成录音里占据已知的时间区间 `[start_seconds, end_seconds]`（`SyntheticSource` 已有这两个字段）。

对每个 AI encounter，计算它和每个素材的重叠秒数。重叠超过素材时长 30% 的算「覆盖」。

然后归类：

```go
type MaterialMatch struct {
    MaterialIndex   int      `json:"material_index"`      // 素材序号（1-based）
    RecordingID     int64    `json:"recording_id"`
    StartSeconds    int      `json:"start_seconds"`
    EndSeconds      int      `json:"end_seconds"`
    Summary         *EncounterSummary `json:"summary,omitempty"`  // 患者/主诉/处置

    Verdict         string   `json:"verdict"`             // matched/merged/oversplit/missing
    MatchedEncounters []int  `json:"matched_encounters"`  // 对应的 AI encounter seq
    MergedWith      []int    `json:"merged_with,omitempty"`// 被和哪些素材合并了
}

type EncounterMatch struct {
    Seq             int      `json:"seq"`
    StartSeconds    int      `json:"start_seconds"`
    EndSeconds      int      `json:"end_seconds"`
    Summary         *EncounterSummary `json:"summary,omitempty"`

    Verdict         string   `json:"verdict"`             // matched/swallowed/partial
    CoveredMaterials []int   `json:"covered_materials"`   // 覆盖了哪些素材
}

type MatchReport struct {
    MaterialCount   int              `json:"material_count"`
    EncounterCount  int              `json:"encounter_count"`
    MissedCount     int              `json:"missed_count"`      // 被合并掉的素材数
    OversplitCount  int              `json:"oversplit_count"`   // 被切碎的素材数
    Materials       []MaterialMatch  `json:"materials"`
    Encounters      []EncounterMatch `json:"encounters"`
    Seams           []SeamDetail     `json:"seams"`             // 接缝详情，供「看详情」用
}

type SeamDetail struct {
    AfterMaterial   int    `json:"after_material"`     // 在第几个素材之后
    AtSeconds       int    `json:"at_seconds"`
    GapType         string `json:"gap_type"`
    GapSeconds      int    `json:"gap_seconds"`
    Detected        bool   `json:"detected"`           // AI 是否切开了
    BeforeText      string `json:"before_text"`        // 接缝前最后几句（带时间戳）
    AfterText       string `json:"after_text"`         // 接缝后最前几句（带时间戳）
    AIConfidence    float64 `json:"ai_confidence,omitempty"` // AI 对覆盖该接缝的 encounter 的置信度
}
```

`MatchReport` 加进 `SyntheticRunResult`（或 job 的响应里），和现有 `EvalReport` 并存。

## 素材摘要（后端）

左列要显示每个素材的「患者 / 主诉 / 处置」。做法：**保存用例时就生成一次，存进用例文件里**，不要每次运行都重新调 LLM。

在 `POST /internal/split-demo/synthetic/cases` 保存时，对每条素材录音的转写文本调一次现有的摘要接口（`SummarizeEncounterText`），把结果存进 `SyntheticSource`：

```go
type SyntheticSource struct {
    // ... 现有字段
    Summary *EncounterSummary `json:"summary,omitempty"`  // 新增
}
```

预览时也顺便生成（`POST /synthetic/preview`），这样保存前就能看到素材内容对不对。

## 统计指标怎么处理

现有的 `EvalReport`（召回率、精确率、按信号类型分组、平均偏移）**不删除**，但降级：

- 移到结果区最底部
- 用 `<details>` 折叠，标题「详细指标（边界精度）」
- 默认关闭

理由：用例多了以后这些指标有用（能看出哪种信号最弱），但单个用例的场景下人不需要看。

## 顶部结论行的措辞

按结果自动生成，一句话说清：

| 情况 | 文案 |
|---|---|
| 全对 | `放进 3 段素材 → AI 切出 3 次就诊 → 全部正确 ✓` |
| 有漏切 | `放进 3 段素材 → AI 切出 2 次就诊 → 漏了 1 段（严重）` |
| 有过切 | `放进 3 段素材 → AI 切出 5 次就诊 → 多切了 2 段` |
| 混合 | `放进 3 段素材 → AI 切出 3 次就诊 → 漏 1 段、多切 1 段` |

「漏了」后面标注「（严重）」并用红色，因为它对应临床安全风险。

## 验收标准

1. 跑完一个 2 素材的用例，能看到左右两列卡片，每列显示患者/主诉/处置
2. 漏切的素材标红，并说明「被合并进就诊 #N」
3. 点「看详情」能看到接缝前后的原文对话（带时间戳）和 AI 的置信度
4. 顶部一行文字说清「放进几段、切出几段、错在哪」
5. 召回率等统计指标折叠在最底部，默认不展开
6. 素材摘要在保存/预览用例时生成一次，运行时不重复调 LLM

## 不改的

- `EvalReport` 的计算逻辑不动
- 切分核心逻辑不动
- 其他两个页面不动
