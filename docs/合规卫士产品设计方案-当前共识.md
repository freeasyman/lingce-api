# 合规卫士产品设计方案（当前共识）

## 1. 产品定位

合规卫士不是简单的“风险报警系统”，而是：

> 从录音、病历、宣传内容、企业微信聊天记录等材料中，找出值得医院人工判断的具体问题，并提供原文证据。

系统只提出需要医院判断的发现，不自动确认违规、不定责、不处罚。

## 2. 产品价值

### 对医院

- 减少医务科、质控科人工抽查大量材料的时间；
- 让工作人员直接看到需要判断的具体内容和原文证据；
- 面对院长、科主任和监管检查时，可以按场景、人员、科室和规则追溯；
- 通过规则和提示词持续调整检查标准；
- 保留分析执行记录和人工核查记录，保证过程可追溯。

### 对具体使用人

- 医务科、质控科：集中查看和处理待核查发现；
- 科室主任：查看本部门相关发现并了解具体原话；
- 院长：查看全院待核查数量、已确认问题和主要分布；
- 规则维护人员：维护医院关注的检查标准；
- 系统管理员：维护人员、角色和权限。

## 3. 核心业务流程

```text
数据接入
  -> 合规引擎检查
  -> 没有命中问题：放过并保留执行记录
  -> 命中问题：生成一条或多条发现
  -> 人工核查
  -> 保存核查结论和理由
```

### 发现的定义

发现是合规引擎根据一条规则，从一次输入中识别出的、需要医院人工判断的具体问题。

- 同一次输入中，同一条规则出现多处相关内容：一条发现，附带多段证据；
- 同一次输入中，不同规则分别命中：生成多条发现；
- 不同输入不合并为一条发现；
- 没有命中任何问题：不生成发现，不进入待核查列表。

### 人工核查结论

第一版支持：

- 成立；
- 不成立；
- 无法判断。

“整改”不是自动产生的结果。只有医院确认需要后续处理时，才在后续版本中增加相应的后续处理功能。

## 4. 核心功能

- 按场景、角色和规则检查录音、病历、宣传内容等材料；
- 读取对应场景的提示词和规则；
- 生成带有事实、原文证据、摘要和理由的发现；
- 查看发现对应的原始材料和证据；
- 人工核查并填写结论、理由；
- 按人员、科室、场景、规则和时间查询；
- 导出核查结果；
- 保存每次分析执行记录和人工操作记录；
- 管理医院自己的检查标准；
- 管理基本人员和权限。

数据来源的接入配置放在灵策智能运营门户统一管理，不在合规卫士内部重复建设。合规卫士接收已经标准化的业务材料。

## 5. 第一版菜单

### 全院情况

展示：

- 当前待核查数量；
- 已确认问题数量；
- 已核查但不成立的数量；
- 按场景、科室、人员和规则的简单统计。

第一版不在这里加入复杂的治理方案或自动管理举措。

### 待核查

显示尚未人工处理的发现。

列表至少直接显示：

- 谁；
- 哪个场景；
- 哪条检查标准；
- 哪段原话；
- 当前状态。

进入后可以查看原文证据并完成核查。

### 已核查

显示已经处理过的发现，包括：

- 成立；
- 不成立；
- 无法判断。

同时显示核查人、核查时间、核查理由和历史记录。

### 检查标准

用于查看和维护规则：

- 按场景和角色查看规则；
- 增加规则；
- 编辑规则；
- 新建规则版本；
- 启用或停用规则；
- 查看规则使用情况。

提示词属于分析配置，第一版不再单独制造复杂的提示词管理菜单。

### 人员与权限

用于管理：

- 医务科、质控科、科室主任、院长等人员；
- 谁可以查看发现；
- 谁可以执行核查；
- 谁可以维护检查标准；
- 谁可以查看分析和审计记录。

## 6. 规则维护设计

### 增加规则

允许增加规则，并明确：

- 适用场景；
- 适用角色；
- 规则编码；
- 规则名称；
- 判断标准；
- 规则版本；
- 是否启用。

### 编辑规则

- 草稿规则或从未使用的规则可以直接编辑；
- 已经用于分析的规则不直接覆盖；
- 已使用规则的修改必须新建版本；
- 历史版本继续保留，供历史结果追溯。

### 规则版本

每次正式改变判断标准，都形成新的规则版本。

一次分析必须记录当时使用的规则版本，保证以后可以回答：

> 这条发现是在什么规则下产生的？

### 启用和停用

- 新规则默认启用；
- 停用规则不参与新的分析；
- 停用不影响历史分析和历史发现；
- 重新启用后可以参与新的分析。

### 删除

- 从未使用、没有分析记录关联的规则，可以删除；
- 已经使用过的规则不物理删除；
- 已使用规则只能停用或标记为废弃；
- 历史发现不能因为规则停用或废弃而失去关联。

## 7. 数据和实现边界

第一版坚持以下边界：

- 数据接入、格式统一由灵策智能运营门户及上游业务完成；
- 合规卫士负责规则读取、提示词组装、模型调用、发现生成和人工核查；
- 每次检查执行记录与面向用户的发现记录分开保存；
- 没有发现时只保存执行记录，不生成待核查数据；
- 规则和提示词版本必须随分析结果保存；
- 不默认引入复杂的 Case、Task、治理和报表模型。

## 8. 第一版验收标准

- 正常人不需要理解专业术语即可知道每个菜单做什么；
- 只有命中问题的材料进入“待核查”；
- 每条待核查记录都有明确的规则和原文证据；
- 同一输入同一规则的多段证据不会制造重复工作；
- 人工核查后可以查看明确结论和理由；
- 规则可以增加、编辑、版本化、启用和停用；
- 已使用规则不会因删除操作破坏历史结果；
- 修改规则或提示词后可以重新分析；
- 分析结果和核查记录可以追溯到当时的版本。
