# 企业微信三模式审计说明

更新时间：2026-08-16

## 1. 目的

本说明文档对应企业微信三模式彻底重构前的只读审计阶段。

本次审计主要解决三个问题：

1. 当前生产数据里还残留多少历史兼容结构
2. 哪些数据问题会阻塞删除运行时 fallback
3. 接口调用许可与企业上下文来源，在现有数据结构里是否已经能被稳定表达

## 2. 审计脚本目录

目录：

- `scripts/sql/wecom_mode_audit/`

脚本列表：

1. `01-wecom-user-bindings-audit.sql`
2. `02-wecom-corp-installs-audit.sql`
3. `03-wecom-suite-tickets-audit.sql`
4. `04-tenant-wecom-apps-audit.sql`
5. `05-wecom-cross-table-audit.sql`

## 3. 审计关注点

### 3.1 `wecom_user_bindings`

重点检查：

- 空 `mode`
- 空 `provider_app`
- 按新目标主键重复
- 按旧主键重复
- 同一企业微信身份绑定多个员工
- 绑定租户与员工租户不一致

### 3.2 `wecom_corp_installs`

重点检查：

- 空 `mode`
- 空 `provider_app`
- 空 `tenant_id`
- 空 `agent_id`
- 空 `permanent_code`
- 同一 `corp_id` 重复
- 同一 `(mode, provider_app, corp_id)` 重复

### 3.3 `wecom_suite_tickets`

重点检查：

- 空 `mode`
- 空 `provider_app`
- 同一 `mode/provider_app` 下多个 `suite_id`

### 3.4 `tenant_wecom_apps`

重点检查：

- 空 `corp_id`
- 空 `agent_id`
- 空 `secret_ciphertext`
- 同一租户多条自建配置
- 同一 `corp_id` 多条自建配置

### 3.5 跨表一致性

重点检查：

- 绑定找不到对应 install
- 第三方 install 的租户与绑定租户不一致
- 自建绑定找不到租户应用配置
- 第三方 install 却没有 `provider_app`

## 4. 输出用途

本次审计结果将直接用于：

1. 生成企业微信三模式审计结果报告
2. 生成正式迁移方案
3. 决定何时可以删除以下兼容逻辑：
   - `GetAnyUserBinding`
   - suite ticket fallback
   - corp install fallback
   - binding 写入兼容逻辑
   - 代开发 install 穷举识别
