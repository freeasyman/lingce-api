# 企业微信三模式最小回归操作手册

更新日期：2026-08-16

## 1. 目的

本文只回答一个问题：

现在开始真实回归验证时，按什么顺序、做什么最少动作。

## 2. 总顺序

必须严格按下面顺序执行：

1. 自建应用 `self_built`
2. 标准应用 `partner_standard`
3. 代开发应用 `partner_template`

原因：

1. 自建应用依赖最少；
2. 标准应用与代开发应用都依赖服务商侧回调；
3. 先把最简单链路跑通，能更快排除 H5 / OAuth / 绑定基础问题。

## 3. 自建应用最小操作

### 3.1 前置确认

1. OPS 中已有该租户 `corp_id / agent_id / secret`
2. 企业微信后台已配置：
   - 应用主页
   - 可信域名
   - JSAPI 域名
   - 企业可信 IP
3. 测试员工在可见范围内

### 3.2 操作步骤

1. 从企业微信工作台进入应用
2. 观察是否进入 H5
3. 触发企业微信登录
4. 验证首次绑定或直接登录
5. 再次关闭并重新进入
6. 验证是否自动登录
7. 发送一条测试提醒

### 3.3 验收结果

必须同时成立：

1. 页面可进入
2. OAuth 成功
3. 绑定成功或自动识别成功
4. 二次进入成功
5. 提醒消息送达

## 4. 标准应用最小操作

### 4.1 前置确认

1. 服务商配置已存在：
   - `partner_standard.app_id`
   - `partner_standard.app_secret`
   - `partner_standard.token`
   - `partner_standard.encoding_aes_key`
   - `partner_standard.callback_base_url`
2. 标准应用已可生成安装链接
3. 客户企业管理员可执行安装授权

### 4.2 操作步骤

1. 调用 `GET /api/v1/wecom/partner-standard/install-url`
2. 用返回的安装链接执行客户安装
3. 验证 `/install/callback` 是否成功
4. 验证是否生成 `wecom_corp_installs`
5. 员工从企业微信进入应用
6. 验证 OAuth 登录
7. 验证首次绑定
8. 验证二次进入自动登录
9. 发送测试提醒

### 4.3 验收结果

必须同时成立：

1. 安装成功
2. 回调成功
3. 实例落库成功
4. 登录成功
5. 绑定成功
6. 提醒成功

## 5. 代开发应用最小操作

### 5.1 前置确认

1. 服务商配置已存在：
   - `partner_template.app_id`
   - `partner_template.app_secret`
   - `partner_template.token`
   - `partner_template.encoding_aes_key`
   - `partner_template.callback_base_url`
2. 模板可正常扫码安装
3. 企业应用创建路径已可用

### 5.2 操作步骤

1. 客户企业扫码安装模板
2. 完成企业应用创建
3. 验证 `/enterprise-callback` 是否通过
4. 验证实例是否写入 `wecom_corp_installs`
5. 员工从企业微信进入应用
6. 验证 OAuth 登录
7. 验证首次绑定
8. 验证二次进入自动登录
9. 发送测试提醒

### 5.3 验收结果

必须同时成立：

1. 模板安装成功
2. 企业回调成功
3. 实例归属成功
4. 登录成功
5. 绑定成功
6. 提醒成功

## 6. 每一步都要同时看 4 类结果

不允许只看页面。

每一步都必须同步看：

1. 页面表现
2. API 日志
3. 数据库表结果
4. 企业微信实际结果

## 7. 遇到失败时的处理原则

出现失败时：

1. 先停止进入下一个模式；
2. 先记录失败步骤和现象；
3. 先确认是页面问题、回调问题、数据问题还是许可问题；
4. 修完后重跑当前模式，不允许跳模式带病继续。
