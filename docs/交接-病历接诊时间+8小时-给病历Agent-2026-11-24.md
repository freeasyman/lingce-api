# 交接（给电子病历开发 Agent）：病历「接诊时间」比录音时间晚 8 小时

- **日期**：2026-11-24
- **提出方**：录音端 / 发布侧
- **结论先行**：**录音上传时间是对的**，问题出在**病历侧写入 `started_at` 时把北京时间当成了 UTC**。

---

## 一、先回答：上传的时间是对的

`recordings.recorded_at` 的写入方式：

- **桌面端上传**（`source=desktop`）：`CreateOwnedAudioRecording` 用
  `COALESCE($18::timestamp, NOW())`，上传请求不传 `recorded_at`，所以取数据库 `NOW()`
  （会话时区 `Asia/Shanghai`）→ 存的就是**上传那一刻的北京时间**。
- **工牌**（`source=smart_badge`）：`recorded_at` 由设备上报，比 `created_at` 早几分钟到半小时（批量同步），
  与占位客户名里的时间一致。

生产库实测（2026-11-24 14:35）：

| recording | source | recorded_at | created_at | 差 |
|---|---|---|---|---|
| 2423 | desktop | 2026-11-24 **14:18:39** | 14:18:39 | 0 秒 |
| 2424 | desktop | 2026-11-24 **14:19:07** | 14:19:07 | 0 秒 |
| 2422 | smart_badge | 2026-11-24 **13:59:29** | 14:03:37 | 248 秒（正常上传延迟） |
| 2419 | smart_badge | 2026-11-24 **12:08:00** | 12:40:40 | 1961 秒（批量同步） |

→ **`recordings.recorded_at` 存的是正确的北京时间**，不需要改。

## 二、我的检查结果：病历的 `started_at` 多了 8 小时

`emr_records.started_at` 是 **timestamptz**，与 `recordings.recorded_at`（timestamp without time zone，北京时间）对比：

```sql
SELECT er.id, er.started_at, r.recorded_at, r.source,
       extract(epoch from (er.started_at - (r.recorded_at AT TIME ZONE 'Asia/Shanghai')))/3600 AS diff_hours
FROM emr_records er
JOIN encounters e ON e.id = er.encounter_id AND e.source_type='recording'
JOIN recordings r ON r.id = e.source_id
ORDER BY er.created_at DESC;
```

结果（7 行，**全部恰好 +8.00 小时**）：

## 三、根因（一条链，问题在最后一跳）

1. `recordings.recorded_at` 是 `timestamp without time zone`，值是**北京时间**；
2. `pgx` 读出来给的是 **UTC location**（挂钟值仍是 22:53）；
3. worker 在 `lingce-worker/internal/job/business_api.go` 里
   `input.RecordedAt.Format(time.RFC3339)` → 输出 **`2026-11-19T22:53:40Z`**（标成了 UTC）；
4. `lingce-api` `internal/emrrecord/internal_handler.go` 的 `parseRecordedAt` 解析后 `.UTC()`，
   写入 `emr_records.started_at`（timestamptz）→ 实际存成 `22:53:40Z` = **次日 06:53:40+08**；
5. 列表按北京时间展示 → 用户看到 **+8 小时**。

## 四、建议的修法（请电子病历侧处理）

**推荐：写入 `started_at` 时不要盲信 payload 的 `recorded_at`，以录音表为准。**

`SaveGeneratedWorkingDraft` 落库前，用下面这条 SQL 解析出真正的接诊时刻：

```sql
SELECT recorded_at AT TIME ZONE 'Asia/Shanghai'
FROM recordings
WHERE id = $recording_id;
```

- 若拿不到录音（历史数据/手工建病历），再回退用 payload；
- 回退时，**如果 payload 的 `recorded_at` 以 `Z` 结尾且来源是录音**，要按 `Asia/Shanghai` 重新解释，
  不能直接 `.UTC()`。

另外两处也建议一起改：

1. `parseRecordedAt` 解析失败时用 `time.Now().UTC()` 兜底，会把错误**掩盖**成「看起来正常但随机」的时间——建议改成返回零值并报错/记录日志；
2. `internal/emrrecord/handler.go` 的 `timePtr`（从历史录音建病历）同样把
   `timestamp without time zone` 当 UTC 用，也需要按 `+08:00` 重新解释。

> worker 侧我也已经改成发送 `+08:00`（`cBeijingTime`，二进制已编好待发布）。
> 两边都改是双保险：worker 修新数据，病历侧兜住历史/其它入口。

## 五、历史数据修正（7 行，建议随修复一起执行）

## 七、电子病历侧修复（已完成 2026-11-24）

### 代码改动（internal/emrrecord/internal_handler.go）

1. **以录音表为权威**：生成落库前新增 `resolveRecordedAt`，按 `payload.recording_id` 查
   `SELECT recorded_at FROM recordings WHERE id=$1`，读到后按 `Asia/Shanghai` 重新解释挂钟值；
   拿不到录音才回退 payload。
2. **`parseRecordedAt` 重写**：兼容 `...Z` / `...+08:00` / 无时区三种形态，统一按**北京时间挂钟值**
   解释（修复 worker 把北京时间标成 Z 的漂移）；解析失败返回**零值**，调用方兜底并用 `log.Printf` 记录，
   不再用 `time.Now().UTC()` 掩盖错误。
3. `handler.go` 的 `timePtr`（历史录音建病历）此前已按 `+08:00` 解释，本次无需再改。

### 历史数据修正（更安全的版本）

原始 SQL 会无条件 `- interval '8 hours'`，若个别行时间本来就是对的会被误伤。
建议加上"偏差确实是 8 小时"的条件（宽容 2 分钟）：

```sql
BEGIN;

-- 预览：应只命中“偏差≈8小时”的录音派生病历
SELECT er.id, er.started_at, r.recorded_at, r.source,
       extract(epoch from (er.started_at - (r.recorded_at AT TIME ZONE 'Asia/Shanghai')))/3600 AS diff_hours
FROM emr_records er
JOIN encounters e ON e.id = er.encounter_id AND e.source_type='recording'
JOIN recordings r ON r.id = e.source_id
WHERE r.source IN ('desktop','smart_badge')
  AND abs(extract(epoch from (er.started_at - (r.recorded_at AT TIME ZONE 'Asia/Shanghai'))) - 28800) < 120;

-- 修正
UPDATE emr_records er
SET started_at = er.started_at - interval '8 hours'
FROM encounters e
JOIN recordings r ON r.id = e.source_id AND e.source_type = 'recording'
WHERE er.encounter_id = e.id
  AND r.source IN ('desktop','smart_badge')
  AND abs(extract(epoch from (er.started_at - (r.recorded_at AT TIME ZONE 'Asia/Shanghai'))) - 28800) < 120;

COMMIT;
```

- 单元测试：`TestParseRecordedAtKeepsBeijingWallClock` / `TestParseRecordedAtInvalidReturnsZero` /
  `TestBeijingWallClockKeepsComponents` 全部通过；
- 实时链路（source=realtime）不受影响。
