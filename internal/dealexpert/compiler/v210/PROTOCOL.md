# v2.1 executable contract — acceptance candidate

Explicit `deal-compiler-v2.1.0-rc7`; legacy default remains v2.0.0. No old implementation files are modified. This is a candidate for independent model evaluation, not an accepted release.

Input retains the complete recording/context/transcript/fact/catalog contract. Additional server-only identity fields: context target_binding, target_customer_id, binding_record_id, consultant_role_verified; each transcript source subject_binding, speaker_id, binding_record_id; facts carry target_customer_id. A cleaned speaker role does not establish these fields. Missing evidence is unresolved. Unbound event records remain in assembly audit, never individual completed facts.

Analysis retains all seven quality dimensions, need/concerns/trust, catalog findings, contact/clinical restrictions, source refs, confidence and unknowns. decision.state excludes completed events and requires a scheme target. A typed condition is independent of coarse intent state. event_reports explicitly distinguish planned/claimed_completed/denied/unknown and model-proposed subjects. Server checks source subject binding before accepting a target_customer event attribution. No report changes a completed business event.

Final card retains old fields but adds recording-scoped intent, event_reports, target_binding and recording_observations. Individual decision/need/concerns/trust require independently bound target sources. Unbound local intent, conditions and observations survive in recording scope; they cannot create personal sales tasks. Source quotes, roles, timestamps, evidence IDs and business facts are server-owned. Current final schema retains compatibility enums but compiler's model input cannot produce completed intent.

Actions use finite type/template pairs. Sales requires confirmed target, contact authorization, supported personal decision, no contact/clinical restriction and no existing payment/deposit. Internal review/handoff may survive unresolved identity. Templates contain no model-generated treatment or diagnosis. Internal due=within_48h is always system_suggestion; customer_window is a separate original quote plus evidence, requires bound customer source. It is not parsed into a promise/date.

Coach accepts finite communication behaviors and independent behavior/response refs only. Server supplies neutral observation/improvement text, never model-written clinical recommendations, success claims or causal customer-response prose. Clinical risk display is a professional-verification template; raw statement remains an attributed recording observation. Clinical correctness is never certified by the compiler.

Scores additionally require complete coverage, verified consultant occupation and target identity. Natural-language interpretation of need, conditions, secondary findings, product suitability and clinical statements remains an independent semantic evaluation obligation. This candidate does not solve that with keywords or claim type validation proves entailment.

Pending before release: independent model cases and 32-shadow semantic review; remaining field-level confidence types beyond scheme decisions; product/quality narrative semantic evaluation; downstream API/UI/task adapters, explicit run defaults and rollback. None of these may be claimed complete by successful compiler tests.

Scheme decisions now have independent targets, conditions, evidence and scoped confidence objects. Additional decisions use the same full contract as the primary. Personal unknowns cannot inherit model confidence; unbound observations remain recording-scoped. Main decision and first scheme must be identical at card validation. Completed events cannot appear in any scheme intent.

rc7 statement extraction: need/trust/concerns accept typed support (statement_type, local confidence, rune-offset spans) rather than publishing model summaries. Missing/low-confidence/incompatible support is locally withheld with diagnostics. Need requires customer_need; trust requires customer_trust; concerns require customer_feeling/customer_constraint. Source role is only a recording attribution; personal cards still require server-bound target ownership. Recording observations use the same extraction qualification. Spans must address existing, valid customer-labelled transcript sources also listed in the field refs. Complete source utterances are displayed to retain negation/condition context. Span selection is not a semantic proof. Classification and state/target interpretation still require independent model evaluation. No customer_choice may imply fear or trust. Source roles and typed labels do not prove medical claims.
